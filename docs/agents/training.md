## TL;DR

- `training/` builds the model behind `@genclass/runtime`: a Jev-style typed-decision encoder (one forward pass reads a *situation* and answers typed *questions*: choice / noul / score). Owner workstream: TRAIN (CONTRACT §1 says LEAD).
- Two **model candidates**, both with a pruned 16,364-token vocabulary: **R17** (`jhu-clsp/ettin-encoder-17m`, d 256, 7 layers, fresh heads) and **R32** (GenClass 0.1 `jev-local-fast` = ettin-32m, d 384, 10 layers, v1 heads). Final-round-1 decision: R17 on every device (R32 matched it at 3× the latency and size; EVAL.md, RESULTS.md §2). PLAN-v1 adds R68 (student benchmark) and the never-shipped T150 teacher, same vocabulary.
- Pipeline: `prune_vocab.py` (keep first 16,000 BPE merges) → **stage 1** on a synthetic curriculum (`curriculum/`, exact labels, ~55% passive-best decision rows) → **stage 2 / final round** on SIM rows from `sim/` (counterfactual-cost labels) plus curriculum replay → `eval_runtime.py` (product metrics + temperature fit) → `export_runtime.py` (fp16-free int8 **q8** ONNX for WASM, fp16 ONNX for WebGPU) → `ortweb/validate.mjs`.
- `curriculum/rt.py` is a Python port of `packages/runtime/src/situation/*` (+ `state/fields.ts` `changeText`/`stringDiff`) so a share of curriculum rows are **runtime-exact** (byte-identical format to what the runtime sends). It now mirrors the frozen tag **`situation-v2`** (6e5e86e): the new `delivery` trigger (response / WebSocket message about to be delivered), conflict-driven version facts, content facts F1–F3, evidence facts F5–F7/F9, diff-centred string changes, the **2,400-char** full budget and the v2 "auto" device budgets. Any wording change in the runtime situation code must be mirrored there and needs a new freeze tag.
- **v2 data is done and the first v2 runs are training** (LOG 04:50–05:22, NEEDS). SIM v2 gold `train:/data/sim-out/v2-gold` = **10,423,855 rows** (train 7,560,367 / dev 317,732 / test 2,545,756) and unlabeled `v2-unl` = **51,272,078 rows**. `import_v2.sh` + `prep_v2.py` turned the gold into the stream bucket `sim2` (128 train shards), the eval sets `sim2e` (held-out test sample) and `sim2f` (held-out-**feature** test rows), and the v2 curriculum replay `cur5` (300k rows, seed 15, `--p-runtime 0.8`); `v2_node_setup.sh` put the 27 GB tar on every node. Running: **`r17-v2a`** (R17 from `r17-final1`, `mix_v2a`, 8 nodes, ETA ≈ 06:20 UTC, then `v2_post.sh` evaluates on `sim2e`/`sim2f`, runs `eval_gain.py`, exports and serves the tar) and **`t150-v2a`** (teacher, `mix_t150v2`, 11 nodes, ETA ≈ 08:30 UTC). The unlabeled rows and REAL v2 (`v2c1`–`v2c4`, not landed; `import_real.sh` ready) are not imported yet. Everything finished before these runs (all `cur1`–`cur4`/`rt1` sets, `simA`, final round 1, the stopped T150/T1 runs) is situation-v1, and **no situation-v2 model has been evaluated or published yet** (`@genclass/runtime-model` is 404 on npm).
- The scaled program (`training/PLAN-v1.md`): **T150 teacher** (ettin-150m) on v2 gold → `label_teacher.py` / `label_cluster.sh` soft-label a prioritised subset of the ≥ 50M unlabeled rows (PLAN P3: 5–10M rows near the gate plus a uniform sample) → distil students R17 (default) / R32 (/ R68 benchmark) with `launch_student.sh` → **DAgger** rounds on SIM `--on-policy` rows → EVAL → `@genclass/runtime-model@0.1.0`. A **T1** side track (`t1_relabel.py`, `eval_gain.py`, gain head) trains on expected-advantage targets from SIM `meta.cost_futures` (sim/SEPARABILITY.md §7).
- Training itself is `jev_local/train/train.py` in stream mode (DDP over torchrun/gloo on CPU) launched with `scripts/launch_run.sh`; all heavy work runs on Azure VMs (`c01` v1 workbench, `c02`–`c23` F80 nodes (c12–c23 added by `cluster_expand.sh` on 2026-10-08), `train` VM, `data` VM), never on the Mac. Claims per training/NEEDS (05:05 UTC on): SIM finished v2 generation and deallocated its 20 nodes; TRAIN holds **c02** (v2 workbench), **c03–c09, c13** (`r17-v2a`) and **c12, c14–c23** (`t150-v2a`); REAL holds c01, c10, c11 (and `data`) for the `v2c*` batches. The jobs run unattended on the nodes; nothing on our side touches Azure.
- Data mixes (`configs/mix_*.json` → `jev_local/train/stream.py` → `MixConfig`) weight **buckets** = the parent directory names of train shards found under the `--stream` roots; weights are renormalised over the buckets present, so a missing bucket is silently dropped.
- The eval **gate** mirrors CONTRACT §8: candidate = argmax over permitted non-passive actions *A*; fire iff Σ_{a∈A} p(a) ≥ tier threshold (guard 0.9, heal 0.8) and top diagnosis ≠ `expected`. Headline metric: **FIR** (false-intervention rate on passive-best rows).
- Trained checkpoints ship with all-1.0 temperatures; the real `calibration.json` comes from `eval_runtime.py --write-calibration` and must be passed to `export_runtime.py --calibration`.
- Status at this commit: **final round 1** (situation-v1, SIM phase A) is done and is the baseline: R17 81.9% action / 90.5% diagnosis, guard FIR 0.05%, heal FIR 0.24%, ECE ≈ 0.01, but guard recall on clear stale/duplicate cases only 7.7% (EVAL.md); R32 is no better, so **R17 is the default on every device**. The v1 teacher `t150-g1` (stopped at step 69) and the T1 runs (`r17-t1g10`, `r17-t1g20`, `r17-t1h`, stopped at ≈ 1,000–1,350 of 2,168 steps) were halted when situation-v2 was frozen; none has results. The final1 exports exist only on the train VM / Mehar's Mac (`packages/runtime-model/files/` is gitignored); they do not match the v2 runtime. The v2 runs `r17-v2a` and `t150-v2a` (above) have no results in the repo yet. Spend ≈ $440 total to 05:22 UTC, burn ≈ $110/h with 20 nodes (LOG).
- Shell scripts assume a nested checkout: `JEV="$HERE/../.."` must contain `jev_local/`, `scripts/` and `pyproject.toml` (the original `/Users/meharkhanna/jev/<checkout>/training` layout). In this monorepo those live at the repo root, one level up (see Gotchas).

## How it works

### 1. Vocabulary pruning (`training/prune_vocab.py`)

1. `vocab_layout` classifies a byte-level BPE `tokenizer.json`: ids 0–1 added tokens, 2–244 the 243 base byte symbols, 245+i = result of merge i (50,009 merges in ettin), added tokens from 50254 (whitespace runs, specials, `[unused0..82]`, and in GenClass checkpoints the markers `[Q] [O] [L] [T] [F]`). Raises if a merge result is missing or two merges produce the same token.
2. `prune_tokenizer_json(tj, N)` keeps base ids + the first N merge results + all added tokens, checks closure under composition (raises `merges are not closed under composition`), and remaps ids in kept order: ids < 245+N are unchanged, added tokens move down to 245+N.. . It also remaps `post_processor` TemplateProcessing ids and `padding.pad_id`.
3. `prune_hf_dir` slices every `[vocab, d]` (and `[vocab]`) tensor via `index_select` (`slice_weights`, always writes safetensors; reads `pytorch_model.bin` for HF bases), writes `config.json` (`vocab_size` + remapped `*_token_id`), `tokenizer.json`, `tokenizer_config.json` (`added_tokens_decoder` remapped) and `prune.json` (`merges_kept`, `merges_total`, `vocab_old`, `vocab_new`, `embedding_keys`, `source`, `source_tokenizer_sha256`).
4. `prune_checkpoint` (a GenClass fast-engine checkpoint with `backbone/`) prunes `backbone/`, copies `heads.safetensors` and `calibration.json`, and annotates `meta.json` with `vocab_pruned` and `pruned_from`. Written to a temp sibling then renamed.
5. For an HF base (R17), markers are added later by `jev_local/engine/encoder/engine.py` → `init_model` (resize embeddings, seeded marker init), so markers land at the end.
6. `analyze --src ... --group name=a.jsonl,b.txt --merges 8000,12000,...` reports tokens-per-char inflation vs the full vocab (`iter_texts` tokenises state segments `"key: text"`, question headers and items like the packer; `.txt` = one text per line; `--limit-rows` default 2000).

Result used everywhere: N = 16,000 merges → vocab **16,364** = 245 + 16,000 + 119; markers `[Q] [O] [L] [T] [F]` = ids **16359–16363**. R32 and R17 tokenizers are identical (LOG). Inflation at 16k: +10.8% tokens on runtime-like text, +12.3% v1 gen, +10.9% v1 cu (LOG table).

### 2. Curriculum generation (`training/curriculum/generate.py`)

1. `main` builds jobs of `--chunk` (default 5000) rows per split; dev default = max(2000, n/50), test default = max(4000, n/25). Workers run `work(split, chunk, n, seed, out)` with `random.Random(f"{seed}:{split}:{chunk}")`, so output is independent of `--workers` but depends on `--chunk`.
2. `make_row`: test split draws a domain from `TEST_DOMAINS`, else from train domains; builds `App` and `Style.make(rng, test)`; picks a kind from `KINDS` = decision 0.58, ask 0.14, json 0.10, http 0.08, js 0.04, decide 0.06.
3. Decision/ask: pick a trigger from `TRIGGERS` (mutation 0.26, request 0.20, failure 0.18, stall 0.12, inconsistency 0.09, transition 0.08, error 0.07), run its builder → `Scen`, then `rows.decision_row(sc, app, st, rng, P_RUNTIME)` or `rows.ask_row`.
4. `decision_row`: if `p_runtime > 0` and `rng.random() < p_runtime`, call `rt.render(sc, app, rng, info=rinfo)`; on success emit runtime-exact state/questions (trigger and action names from `rinfo`, so a mutation may become a `delivery` row with `apply` relabelled `deliver`; labels restricted to offered actions, 0–2 primitives: choice of (0,0,1,2), `style="runtime"`). Otherwise varied: `situation_state` (≤ 12 facts, shuffled 25%; ≤ 8 state lines; timeline ≤ 16; in-flight ≤ 6; 15% drop one of in_flight/stats/state; 10% shuffle key order; key names from `Style`), `action_question` (10%: rename via `RENAMES`; 15%: insert 1–2 `DISTRACTOR_ACTIONS`; 50% shuffle; descriptions canonical or paraphrased; 10% bare names), `diagnosis_question` (20%: subset keeping gold + `expected` + 2–5 others; 50% shuffle; 10% bare labels), 15% question order swapped, `action` removed if < 2 actions, 0–3 primitives (choice of (0,1,2,2,3)).
5. `_validate` runs `jev_local.serialize.state_segments`, `question_block` and the trainer's `parse_target` on every label; invalid rows are counted in `stats["bad"]`, generator exceptions in `stats["errors"]`; neither is emitted. Each chunk tries at most 3n times.
6. Valid rows get id `cur-{split}-{chunk:05d}-{i:06d}`; `fmt.js_numbers` is applied to `state` and `questions` (integral floats → ints, NEEDS item 8). Chunks are concatenated into `{train,dev,test}.jsonl`; `stats.json` has per-split counters and `passive_best_fraction` per trigger.

Ask rows (`rows.ask_row`): the same `Scen` situation via `situation_state(..., ask=True)` with the trigger line replaced by "Developer question about the current situation." / "ask" / "Question from the app developer.", `facts` dropped 30% of the time (the answer must then come from timeline/state), and 2–5 primitives only (a row with none is discarded). Family `cur/ask/<trigger>`.

Varied-style wording vs the runtime's: `rows.action_question` draws instructions from `fmt.ACTION_INSTR[trigger]` and `rows.diagnosis_question` from `fmt.DIAG_INSTR`. For mutation, request, stall and error the first entry equals the runtime's `ACTION_INSTRUCTIONS`; for failure ("...with this failure?"), inconsistency and transition, and for the diagnosis question ("What is going on here?"), the varied lists do not contain the runtime sentence. The exact runtime instructions (`rt.ACTION_INSTR`, `rt.DIAG_INSTR` = "What is happening here?") appear only in runtime-exact rows. Descriptions: forced canonical (`ACTION_DESC[a][0]`, `DIAG_DESC[d][0]`, = runtime text) 50% of the time, else `pick_from` over the list (which may also return the canonical entry; held-out tails only on test rows).

Row families use the case suffix only: `family = f"cur/{trigger}/{case.split('/')[-1]}"` (e.g. `typeahead/stale` → `cur/mutation/stale`), so builders sharing a case name share a family; `meta.case` keeps the full `"<builder>/<case>"`.

### 3. Runtime-exact rendering (`training/curriculum/rt.py` → `render`, frozen at `situation-v2`)

1. Returns `None` (row falls back to varied style) when `sc.spec` is empty or `spec["no_runtime"]` (still only `failure/offline`: the curriculum never sets the `online: false` spec key that would let `scope_facts` render the v2 offline fact).
2. **Delivery choice (v2).** For a mutation scenario, `spec.get("delivery", rng.random() < P_DELIVERY)` (one RNG draw per mutation row) and `delivery_spec` succeeds (cause = completed OK fetch, or a `ws` op) → the row is rendered as `delivery` if the gold action survives the mapping (see Concepts → Delivery row). `delivery_spec` builds the v2 `DeliverySpec`: channel `response` / `websocket`, predicted writes (`source` `profile` when the signature has a baseline, else `last`; patterns via `normalize_field_path`), `matched` paths, `conflicts_on`, `defers` (spec, default 0), `queued_ahead` 0, `incoming` = `spec["after"]`. When `info` is passed, `render` writes `info["trigger"]` and `info["action_map"]`; `rows.decision_row` relabels with them.
3. Per trigger builds facts as `(text, kind, neutral)` tuples with CORE's computations:
   - `mutation_facts`: provenance; `version_facts` on ≤ 3 paths (non-neutral **only** for a newer-data conflict (`newer_conflict`) or a pending local change (`pending_conflict`), a v2 change from v1 where any other-writer write was non-neutral); `content_facts` when `spec["after"]` exists (F1 "would put the older value back", F2 "would replace text the user typed", F3 "matches the current values ... changes nothing"); `cadence_fact`; `moved_facts` and `concurrency_facts` (both always neutral in v2); cause baseline / failure; `mark_facts`; repetition with `repeat_evidence` (F7) for separate user actions; delta via `change_text` (diff-centred `string_diff` for long strings).
   - `delivery_facts` (new): arrival line ("The response to … arrived after …; the app has not seen it yet." or the WS message line), cause provenance, predicted-writes profile, `version_facts` (conflicted paths first), `pending_revert_facts` + `content_facts` against `incoming`, `mark_facts`, `cadence_fact`, `moved_facts`, `concurrency_facts`, usual latency, preceding failure streak.
   - `request_common` (adds `repeat_evidence`), `failure_facts` (adds F5 `commit_ambiguity` for methods other than GET/HEAD/OPTIONS: a "usually return without processing" sentence for `NOT_PROCESSED` = {502, 503, 429, 408}, a "may have applied it" / "well before its usual" sentence for other 5xx, timeouts and network errors, nothing for other 4xx; `scope_facts` over other endpoints of the same origin in the last 10 s, `cadence_fact`), `stall_facts` (adds `scope_facts`, `cadence_fact`), `inconsistency_facts` / `transition_facts` / `error_facts` (add `mark_facts`; inconsistency writes use `change_text`).
   - Inputs the curriculum Trace does not model come from optional spec keys that **no scenario sets**: `marks` (F9), `cadence` (F6), `online`, `clicks` (F7 multi-click), `defers`, `message_summary`, `delivery` (force). So F6/F9 facts, the offline fact and multi-click evidence never appear in curriculum rows; read-your-writes and list-item joins are not modelled at all.
4. `order` sorts non-neutral first, then by `RANK` (invariant/transition/error 0, versions 1, repetition 2, inputs 3, outcome 4, baseline 5, concurrency 6, provenance 7, request 8, cache 9, delta 10, plugin 11), stable; identical to `packages/runtime/src/situation/facts.ts` → `RANK`.
5. Sections: `subject_sentence` (v2 delivery: "The response to … arrived and is about to be delivered; <predicted_text>." / "A WebSocket message … arrived and is about to be delivered; …"), `in_flight_lines`, `event_lines` (timers omitted, like CORE; write lines use `change_text`), `state_lines`, `stats_lines` ("F of last N failed" over ≤ 20 outcomes via `failure_counts`).
6. Budget: `GC_RT_BUDGET` env (analysis) or `spec["budget"]` or a draw from `BUDGETS` = 2400 (0.35) / 2000 (0.20) / 1667 (0.05) / 1333 (0.05) / 1000 (0.35), i.e. WebGPU/unknown 2,400 and WASM 1–4 threads 1,000 / 1,333 / 1,667 / 2,000 (`packages/runtime/src/runtime.ts` → `situationBudget`). `to_state` applies `section_limits` (linear between `COMPACT_BUDGET` 1100 and `STATE_CHAR_BUDGET` **2400**, `MIN_BUDGET` 500) then shrinks timeline (oldest first) → state → facts (floor 1) → in_flight → stats until `size_chars` ≤ budget; mirrors `packages/runtime/src/situation/serialize.ts` → `toJevState`.
7. Questions: `diagnosis` always, with `DIAG_INSTR` "What is happening here?" and `DIAGNOSES` (10 labels); `action` only if ≥ 2 of `TRIGGER_ACTIONS[trigger]` are among the (mapped) offered actions, with `ACTION_INSTR[trigger]` (delivery: "What should the runtime do with this response or message?") and descriptions from `TRIGGER_DESCRIPTIONS[trigger]` first, else `ACTIONS` (= `questions.ts` → `actionDescription`). At budget ≤ `COMPACT_QUESTIONS_MAX` (1400) every criterion is `null` (bare labels), as in `questions.ts` → `buildQuestions`.
8. Details that matter for byte parity: `app` = `"{app.title} — {app.route()}"`; an empty list section becomes the string `"none"`; `size_chars(state)` = Σ over keys of `len(key) + 2 + len(text) + 1`, where `text` is `"\n".join(value)` for a list and `str(value)` otherwise (= `serialize.ts` → `stateChars`); `failure_text` prints `HTTP <code>` and appends the `world.STATUS_TEXT` reason phrase for a deterministic ≈ 30% of ops (`(op.id * 2654435761) % 10 < 3`), because `Response.statusText` is usually empty in browsers and in SIM. Spec keys `extra_facts` (rendered as `plugin`-kind facts) and `budget` are read by `render` but no scenario sets them. Mutation and delivery rows add `spec["state_extra"]` paths (e.g. the query field) to the state section.

### 4. Training (stage 1, stage 2, final round)

1. Sync code to a node: `training/node.sh HOST sync` (rsync `training/` → `~/gcl-train/training/` with `--delete`; `jev_local`, `scripts`, `pyproject.toml` → `~/jev/`).

### 6. Evaluation (`training/eval_runtime.py` → `main`)

1. `load_rows` reads `<data>/<split>.jsonl` (with `--limit`), keeps `meta`, `labels`, `family` and a `_budget` bucket: `meta.budget` (or `meta.situation.budget`) when present (SIM), else by state chars `≤1100` / `≤2100` / `>2100`.
2. `get_records` → `collect` calls `jev_local/train/eval.py` → `collect` (banded encoder, `max_len` from ckpt meta, default 2048) and keeps one record per supervised question `{id, qid, kind, labels, logits, target, header}`; `header` is `sha1(header)[:12]`. With `--records-dir`, raw logits are cached as `<ckpt.name>__<data.name>__<split>.jsonl` and **reused whenever the file exists**.
3. Calibration: `--calibration file` loads `noul/choice/score/by_header` (action and diagnosis use `choice`). `--fit-split dev` instead fits: `fit_tau` (golden section on log τ in [0.2, 5], 40 iterations, soft-target NLL) for `choice` (all choice questions incl. standing ones), `score`, `action`, `diagnosis`; `fit_tau_noul` (61-point log grid in [0.2, 5]); `by_header` for standing-question headers with ≥ 300 records. A split-half check fits on even `crc32(id)` and scores odd ids.
4. For each mode in raw/kind/group/header (only raw without temperatures): `question_metrics` (per group `action`, `diagnosis`, `choice`, `score`, `noul`, `all`: n, acc, NLL, Brier, ECE with 15 bins) and `decision_metrics`.
5. `decision_metrics` (rows with both `action` and `diagnosis`): maps shown names back with `meta.action_names` (`canonical`; for curriculum delivery rows `deliver` maps back to `apply`); passive-best = gold == `PASSIVE[trigger]` (fallback `meta.passive` for triggers not in `PASSIVE`, which includes v2 `delivery`) or `TIER[gold] == "passive"` (`deliver` is passive, so SIM delivery rows work); per mode guard (guard tier) / heal (guard + heal): *A* = offered actions whose tier is permitted (unknown names default to heal), candidate = argmax p over *A*, fire iff Σ p(A) ≥ `THRESH[tier(candidate)]` and top diagnosis ≠ `expected`. Counts FIR, precision (candidate == gold), recall (on rows whose gold is a permitted non-passive action), and with `meta.costs`: mean cost of policy / always-passive / oracle and harm on passive rows. Breakdowns `by_trigger`, `by_case`, `by_style`, `by_budget`; `sweep` at 0.5/0.6/0.7/0.8/0.9/0.95 (heal set); `diag_confusion`; top-30 `false_fires_detail` (`mode:trigger:cand<-gold`).
6. `primitive_acc` per qid family (trailing digits stripped). Report JSON to `--out`; `--write-calibration` writes `{noul, choice, score, by_header, _fit}` (`by_header` only with `--header-calibration`, else `{}`). The fitted `action` / `diagnosis` temperatures are only recorded in `_fit.taus`: the shipped file applies `choice` to the standing questions unless `--header-calibration` adds their exact headers (lookup is by header, then by kind, with optional `by_bucket` / `tau_k` / `noul_platt` steps in between that these files never contain; there is no per-qid key: `packages/runtime/src/model/calibrate.ts`, `jev_local/engine/encoder/calibrate.py` → `calibrate_logits` / `tau_for`). If both `--calibration` and `--fit-split` are given, the fit wins. Console prints the `kind` mode summary.
7. Report layout: `ckpt, data, split, n_rows, n_questions, taus, calibration_from | calibration_fit_on, split_half{taus_even, odd_raw, odd_with_even_taus_{kind,group,header}}, questions_<mode>{<group>: {n, acc, nll, brier, ece}}, decisions_<mode>{n, action_acc, diag_acc, modes{guard,heal}, by_trigger, by_case, by_style, by_budget, sweep, diag_confusion, false_fires_detail}, primitive_acc`. Each `modes.<m>` = `{false_intervention_rate, false_fires, passive_rows, precision, fires, recall, active_rows, recall_clear, clear_rows, recall_clear_stale_dup, clear_stale_dup_rows[, mean_cost{policy, always_passive, oracle, rows, harm_on_passive_rows}]}`. Clear rows (added for PLAN-v1's recall target): not passive-best, gold permitted in the mode, and the gold target's max probability ≥ 0.9; a hit = the gate fires with the gold action; the `_stale_dup` pair restricts to gold diagnosis `stale` or `duplicate`.
8. Batch drivers: `run_evals.sh TAG M...` (stage 1, per model in parallel): `rt1` test with `rt1` dev fit → `out/cal/<M>.json`, then SIM sample (`data/simsample/test.jsonl`, how it was created from `sim/samples/sample.jsonl` is not scripted) with that calibration; `cur1` test with its own dev fit; `cur2` test raw. `eval_sim.sh NAME M...`: for every shard dir `data/NAME_t*` (test) and `data/NAME_d*` (dev) it runs `eval_runtime.py --records-dir out/records --batch 32 --threads $EVAL_THREADS` in parallel only to fill the logit cache, concatenates `out/records/<M>__NAME_t*__test.jsonl` → `<M>__NAME__test.jsonl` (same for dev), then one `eval_runtime.py --data data/NAME --split test --fit-split dev --write-calibration out/cal/<M>-NAME.json` reads the merged cache.
9. `training/report.py name=report.json ... [--mode=kind]` (default `kind`; falls back to `raw` when the report has no `decisions_<mode>`) prints the EVAL.md tables (main table, clear-case recall table (guard/heal × all/stale+duplicate, with row counts), SIM cost table when `mean_cost` exists, per trigger, per budget, sweep, taus + split-half NLL/ECE).

### 7. Export (`training/export_runtime.py` → `main`)

1. `load_checkpoint(--ckpt, encoder="reference")`; calibration = `--calibration` file if given, else the checkpoint's (all 1.0 after training). `ExportModel(enc, heads)` and `plan_inputs`/`unpack` are imported from `scripts/genclass_export.py` (single source of the graph; same I/O as GenClass 0.1).
2. Parity requests: `--requests file` or `requests_from_rows(--data-rows, --n-per-file (40), max_tokens 1500)` (random rows per file, seed 0). Written to `requests.json`.
3. `torch.onnx.export` (opset `--opset` 17, `dynamo=False`, dynamic axes L/G/K/S/K2/M) of fp32 and a `.half()` copy into `--out/ref/` (`<name>-fp32.onnx`, `<name>-fp16-fullemb.onnx`).
4. `make_q8`: `gemm_to_matmul` (Gemm with transA=0, alpha=beta=1 → MatMul + Add, so the noul head's first layer is quantised too) → onnxruntime `MatMulNBitsQuantizer` (`DefaultWeightOnlyQuantConfig(block_size=--block 32, is_symmetric=True, bits=8, op_types_to_quantize=("MatMul",), quant_axes=(("MatMul", 0),))`) → `quantize_embedding(..., "float32")` → **fp16 check**: any FLOAT16 initializer or Cast-to-FLOAT16 raises `ValueError` → `onnx.checker` → `<name>-q8.onnx`.
5. `quantize_embedding`: finds the single Gather over a `[vocab, d]` initializer, replaces it with `Gather(int8 table) → Cast → Mul(Gather(per-row scale))`; symmetric per row, `scale = max|row| / 127` (zero rows get scale 1), `q = clip(rint(w/scale), -127, 127)`.
6. `make_fp16`: the fp16 graph + int8 embeddings with fp16 Cast/scale → `<name>-fp16.onnx`.
7. Parity on ORT CPU (fp32, fp16, q8; plus 1-thread sessions for q8/fp16) vs PyTorch `FastEngine(encoder="banded")` with the same calibration → `parity.json`; packer outputs → `pack_fixtures.json`; PyTorch logits/probs/header keys → `torch_fixtures.json`.
8. Model directory: `tokenizer.json` (copied from `ckpt/backbone`), `calibration.json`, `meta.json`, `model.json` (card). `ref/` is not part of the card and is excluded from delivery tars.

CLI defaults: `--name genclass-runtime`, `--version 0.1.0` (always pass both; the delivery convention is `genclass-runtime-r17` / `-r32`), `--requests` or `--data-rows` is required in practice (with neither, the request list is empty and `main` raises on `max(packs, ...)` before exporting; the requests also fix the dummy shapes used for tracing), `--n-per-file 40`, `--opset 17`, `--threads 16`, `--block 32`. The parity packer is `Packer(tok, max_len=8192)`. `meta.json` `merges_kept` is read from the checkpoint's `meta.vocab_pruned`, which only `prune_vocab.py prune_checkpoint` writes; trainer-written servables (`jev_local/engine/encoder/engine.py` → `write_checkpoint`, called by `jev_local/train/train.py` → `train`) do not carry it, so exports of trained models have `merges_kept: null`.

### 10. T1 expected-gain experiments (`t1_relabel.py`, `eval_gain.py`, `collect_gain.py`)

1. `$PY training/t1_relabel.py --in data/s3/simA --out data/s3/simAg10 --tau 1.0 [--workers 16] [--keep-dist]`: per `*.jsonl` shard in parallel; for each row with an `action` question and label, `gains_of(meta, offered)` uses `meta.cost_futures` (falls back to `meta.costs` as single futures), `meta.tiers` and `meta.passive` (falls back to the passive-tier action); gain per offered action with costs = mean passive cost − mean action cost − `PREM[tier]` (unknown tier = heal 0.5), clipped to ±`CLIP` (30); passive = 0. Rows without costs or with < 2 gains are copied unchanged. Default: action label = softmax(gain/τ) over offered actions that have costs (an offered action without costs gets no mass); `--keep-dist`: keep SIM's label and add `labels.action.gain` (ignored by this repo's `parse_target`). Both write `meta.egain`. Prints `{files, rows, relabelled, tau}`.
2. Train on the new bucket (`mix_t1a` / `mix_t1b` / `mix_t1h`); the gain-head run adds trainer flag `--gain-loss W` (smooth-L1, β 2, on `labels.action.gain`), which exists only in the parent-repo `jev_local` (LOG 03:00), not in this monorepo.
3. `t1_post.sh RUN TAU` / `t1h_post.sh RUN` (detached on the run's rank-0 node): wait for `models/RUN/meta.json` `final`, `EVAL_THREADS=12 eval_sim.sh simAe RUN`, (gain head: `collect_gain.py` per `data/simAe_t*` shard with 12 threads, concatenated to `out/records/RUN__simAe__test.gain.jsonl`), then `eval_gain.py`.
4. `eval_gain.py --rows data/simAe/test.jsonl --model name=records:cal[:tau]`: per mode (guard = guard-tier actions; heal = guard + heal), per row `classify` (clear / benign / mild over futures, see Concepts), oracle = Σ max(0, best gain). Policies: `gate@t` for t ∈ {0.5, 0.6, 0.7, 0.8, 0.9, 0.95} (CONTRACT §8 summed-mass gate with the `expected` diagnosis veto; probabilities at the calibration's `choice` τ), `gate@t-nodiag` (no veto; t ∈ {0.5, 0.7, 0.8, 0.9, 0.95}, no 0.6), `gain>m` for T1 models (ĝ(a) = τ·(z_a − z_passive) on raw logits, m ∈ {0, 0.5, 1, 2, 3, 4}), `head>m` and `head>m+diag` for records with `gain_pred`. Metrics: `fired_share`, `recall_clear`, `benign_fired`, `harmful_share` (fired true gain < −1), `gain_captured` (÷ oracle), `net_gain_per_row`, `fir_label` (passive-label rows fired).
5. Baseline (LOG 02:40, R17-final1, heal, 12,901 test decision rows, 912 clear, 9,720 benign, oracle 0.91 gain/row): gate@0.8 captures 6.7% of the oracle gain (recall on clear 8.1%, harmful 0.09%); gate@0.5 31% (recall 38%, harmful 1.3%, label-FIR 5.1%). With τ = 1 the soft labels put ≥ 0.5 non-passive mass on 64% of rows, so a summed-mass gate is the wrong rule for gain-shaped probabilities (T1 needs a per-action gate).

Sampling is `h(id) = crc32(id) % 100000` against rates `round(100000 · test_rows / rows.test)` and `round(100000 · dev_rows / rows.dev)`, so it is deterministic and independent of shard order; the held-out-feature rate is 6× the test rate (capped at 100,000) and keeps test rows whose `family` (or `meta.family`), split on `+`, contains a `TEST_FEATURES` entry, then shuffles (`Random(7)`) and cuts to `--test-rows`. `write_set` writes `data/<name>{e,f}/{dev,test}.jsonl` plus `_t0..3` (test, every 4th row) and `_d0,1` (dev, every 2nd) for `eval_sim.sh`; `sim2f` reuses the `sim2e` dev rows. Prints `{train_rows, train_shards, eval_test, eval_dev, heldout_feature_test}`.
3. **Nodes** (from the Mac, per node): `training/v2_node_setup.sh cNN` (SIM had deallocated the nodes; TRAIN restarted them with `az vm start --no-wait`, one call at a time, LOG). The tar adds `data/s3/{sim2,cur5}` and the eval dirs; `cur1` and `gen` (named by `mix_v2a`) must already sit under `data/s1` from the node kit.
4. **Launch**: `r17-v2a` and `t150-v2a` (table in §4). Both mixtures list `buckets` and cap `sim2` at `max_repeat` 1.0 per pass.
5. **Post** (`v2_post.sh r17-v2a genclass-runtime-r17 2.0.0-rc1`, detached on c09; `set -u`, no `-e`): polls `models/<M>/meta.json` for `final` every 30 s, `EVAL_THREADS=10 eval_sim.sh sim2e <M>` and `… sim2f <M>` (each fits its own temperatures on the shared dev rows: `out/cal/<M>-sim2e.json`, `out/cal/<M>-sim2f.json`), `eval_gain.py --rows data/sim2e/test.jsonl --model <M>=out/records/<M>__sim2e__test.jsonl:out/cal/<M>-sim2e.json --out out/eval/gain-<M>-sim2e.json`, touches `out/.eval-done-<M>`, then `export_runtime.py --calibration out/cal/<M>-sim2e.json --data-rows data/sim2e/dev.jsonl,data/cur5e/dev.jsonl --n-per-file 60 --threads 24` → `out/export-<M>/`, tars it without `ref/` to `~/xfer/export-<M>.tar`, serves `~/xfer` on `<node IP>:8801`, touches `out/.post-done-<M>`. Logs: `logs/v2-eval-<M>-{e,f}.log`, `logs/v2-gain-<M>.log`, `logs/v2-export-<M>.log`. Unlike `final_post.sh` it creates `logs/` first. Delivery to the train VM / MODEL is a separate step (`pull_on_train.sh` pattern); the card version `2.0.0-rc1` is the export's own `model.json` version, not an npm version.
6. **REAL v2** (prepared, not run): `training/import_real.sh "v2c1 v2c2 v2c3 v2c4" v2-eval` (train VM serves `/data/real-out` on :8804; per batch `train`, `dev`, `test`, `unlabeled-train` jsonl; train rows shuffled (`yes 3`) into 32 shards `data/s3/real2/`; `real2e` = 20k test (`yes 4`) / 8k dev (`yes 5`) with `_t`/`_d` shards; `realev` from `real_eval.jsonl` if present; unlabeled into `data/s3/realunl/`). Evaluate a model on `realev` by filling `out/records/<M>__realev__test.jsonl` (e.g. `eval_sim.sh realev <M>`: its per-shard runs and the test merge work, but there are no `realev_d*` shards or `realev/dev.jsonl`, so the unmatched `data/realev_d*` job and the final dev-fitted `eval_runtime.py` step fail; unverified) and then `eval_real.py --rows data/realev/test.jsonl --model <M>=<records>:out/cal/<M>-sim2e.json`. `eval_real.py` applies the calibration's single `choice` τ to both action and diagnosis logits; a missing `meta.tiers` entry counts as heal. The LOG plans a continuation of `t150-v2a` that adds the REAL bucket.

## Invariants and gotchas

- **Runtime parity of `rt.py` is load-bearing.** Constants and wording (`DIAG_INSTR`, `DIAGNOSES`, `ACTIONS`, `ACTION_INSTR`, `TRIGGER_ACTIONS`, `RANK`, `LIMITS`, budgets, `secs`/`rel`/`ratio`/`fmt_num`, `signature`/`is_id`) must equal `packages/runtime/src/situation/{questions,serialize,facts,conflicts,content,evidence,describe,build}.ts`, `src/state/fields.ts` (`changeText`/`stringDiff`) and `src/util.ts`. `rt.py` was ported against tag `situation-v2` (6e5e86e), and all v2 SIM/REAL data was generated against it. On `mvp-v2-merge` the situation code differs from the tag only by the redaction fix (f107013): `situation/content.ts` → `contentFacts` F2 ("would replace text the user typed") now uses `state/fields.ts` → `redactedStringDiff`, and `util.ts` → `isSensitivePath` also redacts numbers, bigints and arrays under a secret-named container. Both only change text for secret-looking paths; `rt.py` has no redactor at all (its F2 always uses `string_diff`), which is harmless as long as curriculum paths never look secret (unverified). Per HANDOFF a change to `situation/*` normally means a new freeze tag; this one has none. Spot-checked earlier at b435acb: `STATE_CHAR_BUDGET` 2400, `COMPACT_BUDGET` 1100, `MIN_BUDGET` 500, `COMPACT_QUESTIONS_BUDGET` 1400, `RANK`, `sectionLimits`, `situationBudget`, `TRIGGER_DESCRIPTIONS`, delivery instruction and `DEFAULT_DIAGNOSES` match; a full byte-parity check against runtime output was not run (unverified). Per-header calibration keys are `sha1(instructions)[:12]`, so any instruction text change silently orphans `by_header` temperatures.
- **Known small parity gaps** in `rt.py`: `to_state`'s last-resort shortening truncates facts to max(40, …) and never shortens the trigger, while `toJevState` uses max(60, …) and then shortens the trigger; Python `round()` (banker's) vs JS `Math.round` in `secs` (≥ 1000 s) and `ratio` (≥ 10×); Python format specs (`f"{x:.2f}"`, half-even on exact binary ties) vs JS `toFixed` (ties up) in `secs`/`rel`/`fmt_num`, e.g. `secs(125)` is `0.12s` in Python and `0.13s` in JS; `truncate` counts code points (Python `len`) vs UTF-16 code units (JS `length`), so text with astral characters such as emoji is cut at different points. Rare, but they produce text the runtime never sends.
- **Numbers as JS prints them.** `fmt.js_numbers` turns integral floats into ints in `state` and `questions` (not in `labels`/`meta`); without it the model trains on `25.0`, which the JS runtime never emits (NEEDS item 8). Keep it when adding new emit paths.
- **Determinism** is per code version: `random.Random(f"{seed}:{split}:{chunk}")`, sorted iteration where sets are involved. Changing any generator code, `--chunk`, or `--p-runtime` from 0 to > 0 (it adds an RNG draw) changes the rows; `cur1`/`cur2`/`cur3`/`cur4` cannot be regenerated byte-identically from the current code (the generator gained `transient`, `coincidental`, budgets and compact questions, and v2 adds a `P_DELIVERY` draw per runtime-rendered mutation row and different facts/budgets).
- **Held-out integrity:** test rows only use `TEST_DOMAINS` and may use held-out templates; train/dev never do. `test_curriculum.py` asserts both. Do not add a domain to `DOMAINS` without deciding its split.
- **Precision first:** decision rows must keep a large passive-best share (test bound 0.45–0.75); soft labels for ambiguous cases lean passive. SIM's passive-best shares are much higher (pre-freeze SIM sample: 70–96% per EVAL.md; phase A train: 64% stall to 99% error, `sim/samples/stats-final-a.json`, see [sim.md](sim.md)), which is why stage 2 is required.
- **Single-action rows** have no `action` question/label (runtime behaviour). `eval_runtime.py` skips them in `decision_metrics`, so `diag_acc` there covers only rows that also have an `action` question.
- **Calibration must be shipped explicitly.** A trained servable's `calibration.json` is all 1.0; `export_runtime.py` without `--calibration` ships uncalibrated temperatures. The runtime gate thresholds assume calibrated probabilities.
- **Stale logit cache:** `eval_runtime.py --records-dir` reuses `<ckpt.name>__<data.name>__<split>.jsonl` if present, even after the checkpoint changed. Delete `out/records/<M>__*` before re-evaluating a retrained model with the same name. `eval_sim.sh` concatenates shard records by this naming.
- **q8 must be fp16-free.** Onnxruntime's WebGPU Gather on an fp16 table requires `shader-f16` ("Program Gather requires f16"); the int8 table + fp32 row scales runs on WebGPU without it (MODEL confirmed in Chromium/SwiftShader). `make_q8` raises on any fp16 tensor or cast; keep the `gemm_to_matmul` rewrite (without it the noul head stays fp32, +2.9 MB).
- **Rank 0 holds the init.** Only rank 0 reads `--resume` state or `--init-from`; the first node in the launcher list must hold the init (for final1: `runs/<model>-s1c/ckpt`, c02 for R32, c09 for R17; the stopped `t150-g1` checkpoint is only on c12's disk). `--resume` wins over `--init-from` when `runs/<run>/ckpt/trainer.json` exists, so reusing a run name resumes instead of re-initialising.
- **Mixture buckets are directory names.** Put shards in `<stream root>/<bucket>/`. Without a `buckets` list, any extra bucket dir under a stream root silently gets weight 0.04 (`OTHER_BUCKET_WEIGHT`); `mix_final1.json` and the newer `mix_t150`, `mix_r68`, `mix_t1a/b/h` list `buckets`; `mix_s1*`/`mix_s2` do not.
- **Marker ids moved.** With the pruned vocab, `[Q] [O] [L] [T] [F]` are 16359–16363; runtime, sim tooling and tests must read them from `tokenizer.json` / `meta.json` (CONTRACT §10). With 16k merges, keys like `trigger`, `facts`, `apply`, `defer` split into several tokens (harmless; trained on the pruned tokenizer).

**Reproduce the pipeline** (Azure only; commands run in `~/gcl-train` via `node.sh HOST '...'`, `$PY` and `G` as above):
1.
