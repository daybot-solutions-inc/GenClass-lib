# realapps/: real-browser training corpus and never-worse harness

> **Scope:** `realapps/**`: `README.md`, `EXAMPLES.md`, `package.json`, `build.mjs`, `.gitignore`, `apps/**` (the
> app catalogue, `apps/README.md` authoring guide, `apps/_shared/**`), `corpus/**` (open-source apps), `src/world/**`
> (in-page world), `src/harness/**` (Node side), `src/shared/**`, `scripts/**`. Also the REAL sections of
> `training/NEEDS.md` (items 13–16) and the realapps parts of [RESULTS.md](../runtime/RESULTS.md) §4/§6 and
> `packages/runtime/STATUS.md` ("Never worse").
> **Read this when:** you need to know what a REAL (`meta.source = "realapps"`) training row is and how it was
> labelled; you add or change an app, a harness rule, a cost term or a diagnosis rule; you rerun the determinism or
> interference ("never worse") sweeps after a runtime change; or you plan a real-browser generation batch.
> **Source of truth:** the code. Verified against branch `mvp-v2` at b435acb (origin/runtime 74f17c0 = situation-v2, plus default mode observe and CI), 2026-10-08. If this doc and the code disagree, the code wins.

## TL;DR

- `realapps/` (owner: REAL, the colleague's workstream) runs **real web apps built with real frameworks** in
  **headless Chromium** (Playwright) with the **real `@genclass/runtime` bundled from source**, on fully virtualised
  time and an in-page mock backend with chaos. It labels sampled runtime decisions by **counterfactual outcome** with
  the **sim's own cost weights and label rule** (it imports them from `sim/src`), and writes **CONTRACT-D rows** in
  the same shape as SIM rows. It closes the sim-to-real gap (React's MessageChannel scheduler, Vue/Svelte microtask
  flushes, TanStack Query/SWR dedupe, XHR libraries, Redux middleware, the apps' own bugs).
- **Corpus at b435acb: 91 apps** (77 written for the corpus + 14 open-source RealWorld "Conduit" front-ends),
  23 distinct `framework` values. `realapps/README.md` and `HANDOFF.md` still say 66 apps and
  `docs/runtime/RESULTS.md` §6 says "66 → ~96"; 25 apps were added after fcb8189 (24 in d73d20c, `preact-mappins` in
  74f17c0; see Drift).
- It is also the runtime's **"never make a correct app worse" harness**: `debug.js --interference` compares observe
  mode with heal mode under an all-passive decider. Situation-v2 result (STATUS.md): **0/396 clean runs changed**
  over all 66 apps then in the corpus, seeds 1–6; 3/198 changed under chaos (an open item per RESULTS.md §4). Under
  situation-v1 the gothinkster React/Redux Conduit never rendered its feed.
- **Nothing here is in CI or the root workspaces, there are no tests and no tsconfig.** Every real step needs
  Chromium, and generation runs on Azure F80 nodes. Under our run policy: **ask the user before running anything
  in `realapps/`** that launches Chromium (`debug.js`, `gen.js`, `chromium_probe.mjs`), clones the OSS corpus
  (`corpus/prepare_oss.sh`), or touches a VM (`scripts/vm.sh`, `realapps/scripts/cluster.sh`, `node_setup.sh`).
- Data status (from `training/NEEDS.md` 16, not verifiable from here): v2 production batches `v2b1`/`v2b2`/`v2b3` on
  c01/c10/c11 (30k trajectories each, target ≥ 500k gold; [HANDOFF.md](../../HANDOFF.md)/[RESULTS.md](../runtime/RESULTS.md): about 495k), to be copied to `train:/data/real-out/`. No training
  code in the repo reads realapps output by name yet; it is consumed as generic CONTRACT-D batches (see
  [training.md](training.md)).

## Concepts and data structures

- **App manifest** (`realapps/src/shared/manifest.ts` -> `AppManifest`): everything the harness knows about an app.
  Key fields: `framework`, `libs`, `domain`, `entry`, `integration: "stores" | "observe"`, `server` (the
  `ServerSpec` the in-page backend serves), `variants` (feature flags; **first option = correct default**),
  `affordances` (what the scripted user can do), `external` (other users' events), `weights` (per store or
  store.field divergence weight), `relations` (derived-field invariants; `fields[0]` is the derived field),
  `domRoot` (default `body`), `errorSelector` (default `[role=alert]`), `domWeight` (default 1), `heldOut`, `source`
  (OSS origin), `startMs`, `localStorage`/`cookies` preloads, `sessionMs` (default `[20000, 60000]`), `build`
  (jsx/jsxMode/svelte/vueCompiler/vite/prebuilt...). The app code never sees the manifest except the server spec and
  the chosen flags.
- **Affordance** (`Affordance`): `id`, `kind` (`StepKind`: click, dblclick, type, clear, select, check, key, hover),
  CSS `sel` (`>>>` pierces shadow roots), `text`, `nth`, `values`, `weight`, `mode` (`replace` | `accumulate`),
  `key`/`intent` (intent key), `clear`, `enter`, `dblclickP`, `impatientP`, `burst`, `after`, `waitMs`, `then`,
  `sameNth`, `followOnly`, `resets`, `requires`, `requiresText`.
- **Integration kinds.** `stores`: the app puts state in runtime stores (`rt.atom`, `useGenClassState`,
  `genclassEnhancer` for Redux/RTK, `genclass()` for Zustand, `rt.guard` for Pinia/MobX, atom bridges for
  Vue/Svelte/Solid/Preact/Lit). `observe`: no stores (17 manifests at b435acb: the jQuery apps, `superagent-fleet`
  and the non-Redux OSS Conduits); they still produce request, failure, stall and error rows, and their divergence is
  measured on visible DOM text. "Observe-only" here is an integration style; the harness still runs these apps with
  `mode: "heal"`.
- **Scenario** (`realapps/src/harness/scenario.ts` -> `Scenario`): one seed determines app, flags (`variant`,
  `patterns`), chaos level (`calm | normal | flaky | degraded | storm`), `NetProfile`, scripted `steps`, `external`
  events, `warmup`/`tUser`/`tEnd`, situation `budget` (3,200 / 2,000 / 1,000 chars at 40/30/30%), simulated
  `modelMs` (6–25 ms), exploration ε (0 / 0.08 / 0.2 weighted 4/3/2; 0 on clean runs), wording `vocab`, `split`,
  `epoch`, `askTimes` (1–3 probes). 8% of scenarios are **clean** (first flag options, calm network, no accidental
  clicks).
- **Runs of one trajectory.** *Ideal* (zero latency, no chaos, no accidental clicks, exactly-once; runtime installed
  but blind: `mode: "observe"`, `model: false`, `decider: null`, all observers off; the probe's hooks and plugin
  still record stores). *Base* (real runtime, exploration, records every
  decision). *Counterfactuals* (one action forced at decision `k`).
- **DecisionRec** (`realapps/src/shared/types.ts`): `k`, `t`, `trigger`, `actions`, `chosen`, `explored`, `fp`
  (hash of trigger, state and questions, used for the prefix check), `subject`, `diagnosis`, `diagWhy`,
  `diagTrace`, plus the `state`/`questions` the runtime handed the decider.
- **Intent pins** (`RunConfig.pins`): the ideal run records the identity words of the list item each step acted
  on; other runs click the visible element whose item matches best (score ≥ 0.6), otherwise the step is skipped and
  charged as a blocked intent.
- **Row** (`realapps/src/harness/trajectory.ts` -> `Row`): CONTRACT-D `{id, split, family, state, questions,
  labels, meta}`. `state`/`questions` are exactly what the runtime handed the decider. Ids:
  `real-<app>-<seed>-d<k>` (decision), `-a<i>` (ask), `-u<k>` (unlabeled), `-s<k>` (diagnosis-only).
  `family = "<program family>/<trigger>"` (or `/ask`).

## How it works

### Build

1. `node build.mjs [app1,app2]` (in `realapps/`) writes `src/harness/apps.gen.ts` (an import of every
   `apps/*/manifest.ts` whose directory does not start with `_`).
2. It bundles `src/world/index.ts` into `dist/world.js` (IIFE) and the harness into `dist/harness/*.js` (ESM, Node
   22, `playwright` external). Alias `@rt/questions` -> `<RT>/situation/questions.ts`, so both the in-page probe
   and `trajectory.ts` read the **runtime's own `PASSIVE` map** (the only symbol imported through it).
3. Every app without `build.vite`/`build.prebuilt` (the 77 written apps and the 3 `esbuild`-kind OSS apps, the
   latter from their `$RW_OSS_DIR` checkout) is bundled by esbuild with aliases
   `@genclass/runtime[/react|/redux|/zustand]` -> `<RT>/index.ts` / `<RT>/adapters/*.ts`, `@realapps/genclass` ->
   `apps/_shared/genclass.ts`, `onnxruntime-web*` -> the stub, plus framework settings (JSX mode, Svelte plugin, Vue
   template compiler). The other 11 OSS apps (`build.vite` or `build.prebuilt`) are built by
   `corpus/prepare_oss.sh` and only reported by `build.mjs` ("NOT BUILT YET" when missing).
4. **Runtime pinning:** `RT = $RW_RUNTIME_SRC ?? ../packages/runtime/src` and `RT_TAG = $RW_RUNTIME_TAG ??
   "working-tree"`. For data, `RW_RUNTIME_SRC` is a `git archive <tag> packages/runtime/src` export
   (`cluster.sh sync` with `TAG=...` does this into `~/gcl/real-cache/runtime/<tag>/src` and writes
   `~/gcl/real-cache/runtime/current`; `node_setup.sh` exports both variables from it). The tag goes to
   `dist/runtime-tag.txt` and from there (`trajectory.ts` -> `RUNTIME_TAG`, `"unknown"` when the file is missing)
   into every row's `meta.runtime`. At b435acb, `packages/runtime/src` differs from `situation-v2` only by our
   default-mode commit f3636b2, which realapps overrides with explicit modes; a working-tree build still stamps
   `working-tree`, not `situation-v2`.

### One run (`realapps/src/harness/browser.ts` -> `Runner.run`)

- A fresh page in a shared context (viewport 1280×900, `en-US`, `UTC`, reduced motion, service workers blocked).
  Chromium flags include `--host-resolver-rules=MAP * ~NOTFOUND` (except localhost), so every external host fails
  DNS and images/fonts never load on real time.
- Init script: `window.__RW_CFG = <RunConfig>` followed by the world bundle. Requests to
  `https://app.example.com/**` are fulfilled from `dist/apps/<app>/` (SPA fallback to `index.html`).
- After `load`, `window.__RW.start()` runs the whole session on virtual time and returns a JSON `RunResult`
  (decisions, snapshots, network log, server state, error episodes, uncaught errors, steps run/skipped, asks).
  Timeout 180 s per run.
- **Runtime options for non-ideal runs** (`realapps/src/world/index.ts`): `mode: cfg.mode ?? "heal"`, the probe's
  decider, `report: "silent"`, `triage: "salient"`, `observe: OBSERVE` (fetch, xhr, user, errors, nav, storage,
  websocket, timers, `untrustedEvents: true`; `perf: false` because long-task timing is real time),
  `policy: { thresholds: { report: 0, guard: 0.5, heal: 0.5 }, holdBudgetMs: 1e9, maxActionsPerMinute: 1e9,
  requireDiagnosis: false }`, `historySize: 500`, `situation: { budget }`, hooks, a probe plugin, and `vocabulary`
  when the scenario rewords. The mode is always explicit, so **our default-mode change (f3636b2, default `observe`)
  does not change any realapps run.**
- **Virtual time** (`realapps/src/world/loop.ts`): tasks run in (virtual time, phase, seq) order; user input runs in
  a later phase than other tasks due at the same instant; after each task the loop yields real macrotasks through a
  captured real `MessageChannel` until tracked native async work (body reads, stream reads) settles. Mock responses
  clone without tee-ing. `ResizeObserver`, `IntersectionObserver` and `PerformanceObserver` are inert.
- **Randomness:** every draw for a request is keyed by (seed, future salt, request identity, occurrence), so forcing
  an action at one decision never shifts unrelated draws. Item ids are content-derived.

### One trajectory (`realapps/src/harness/trajectory.ts` -> `generateTrajectory`)

1. `buildScenario(seed, pool, {clean?})`. Test-split trajectories are kept with probability `testKeep` (otherwise
   `skipped = "test-subsample"`).
2. **Ideal run**; its states define the target and its `pins` define the user's intents.
3. **Base run** with exploration (ε on decisions whose in-page diagnosis is not `expected`, ε/4 elsewhere) and ask
   probes (`runtime.situation("ask")`).
4. **Decision points:** `pickPoints` samples up to `maxPoints` (6) decisions with ≥ 2 actions, weighted by
   `TRIGGER_W` (mutation 1, request 1, failure 1.6, stall 2.2, inconsistency 3, transition 3, error 2.2; anything
   else, including `delivery`, 1) × 1.5 for a non-`expected` diagnosis.
5. For each point and each applicable action: a counterfactual with the base run's explored choices before `k`,
   the action forced at `k`, passive after `k`, stopping at `min(tEnd, t_k + W.finalMs)`. Future 0 reuses the base
   run as the passive counterfactual when the base run chose passive at `k` and explored nothing from `k` on. Futures 1..K-1 (K = `futures`, 3) run
   only when some action beats passive by more than 0.05 in future 0 (`adaptive`); they re-seed draws after `t_k`
   and rerun the ideal when external events fall after `t_k`.
6. **Prefix check:** the counterfactual's decisions `0..k` must have the base run's `fp` values, or the point is
   dropped (`drops["prefix-mismatch"]`). Other drops: `ideal-error`, `base-error`, `cf-error`,
   `ideal-future-error`.
7. **Cost** (`realapps/src/harness/cost.ts` -> `runCost`), sim's weights `W` term by term: divergence area over
   `W.horizonMs`, final client divergence, server damage (content compare, timestamps and ids volatile), relation
   violation area and final, shown errors (store apps: writes that put an error message into a store, counted when
   proposed; observe apps: appearances of the `errorSelector` UI), uncaught errors, wasted requests, pending user
   latency, plus the
   realapps-only **blocked intents** term (`BLOCKED = 1.0` per user step whose element never appeared beyond the
   ideal run's). Client state = registered stores (manifest weights) plus visible DOM text lines × `domWeight`.
8. **Action label:** sim's `actionLabel(costs, passive)` (tier premiums, tie pinning, `p ∝ exp(−gap/τ)`,
   `τ = 0.1 + SE`), then sim's `transformQuestions` (option shuffles/drops, paraphrases).
9. **Diagnosis:** in-page rules (`diagnose.ts`) finished in Node by `finishDiagnosis` (relations, duplicate
   entities, `delivery` handled like `mutation` for `rel-check`). The label is written only when the diagnosis is in
   the row's (possibly reduced) vocabulary; otherwise counted in `notes` (`diagnosis-not-in-vocab`,
   `diagnosis-uncorrelated`). `meta.diag_why`/`diag_trace` say which rule fired.
10. **Ask rows** from the base run's probes, using sim's `askQuestions` generators with exact answers.
11. **Unlabeled rows:** up to `unlabeled` (40) other base decisions with ≥ 2 actions; gold diagnosis only,
    `meta.unlabeled: true`, `base_choice`; action left to the teacher.
12. **Diagnosis-only rows:** up to 3 single-action decisions with a diagnosis in the vocabulary.

### Generation (`realapps/src/harness/gen.ts`)

- Forks `--workers` worker processes (one Chromium each); seeds `seed .. seed+trajectories-1` minus those in
  `done.txt`. Rows append to `{train,dev,test}.jsonl` and `unlabeled-{train,dev,test}.jsonl`; each finished seed
  appends to `done.txt`. `stats.json` and `manifest.json` refresh every 30 s and at the end. Rerunning the same
  command resumes.
- `stats.json`: per trigger (n, passive-best count, best actions, diagnoses, mean harm of non-passive actions on
  passive-best points), per app, drops, notes, skipped, run counts and times, first 50 errors.
- `manifest.json` (for TRAIN, `training/NEEDS.md` 11): seeds, counts, file descriptions, `on_policy: false`,
  held-out frameworks/apps/patterns, app list with OSS repo/commit/licence, options. Its `runtime` field is a
  hard-coded string (see Drift).

### Splits (`realapps/src/harness/scenario.ts` -> `splitOf`)

- **test:** framework in `TEST_FRAMEWORKS` (`lit`), app in `TEST_APPS` (`swr-status`, `alpine-tasks`,
  `xhr-autocomplete`), manifest `heldOut` (only `oss-rtk-conduit`), or a pattern in `TEST_PATTERNS`
  (`react-search/guard:reqid`, `vue-editor/save:serialize`, `zustand-board/push:version-check`).
- **dev:** `hashAll("realapps-dev-v1", app, ...patterns) % 100 < 4`.
- **train:** everything else. Splits are per trajectory, so all rows of a trajectory share one split.

### How it feeds training

- Rows are CONTRACT-D like SIM's, with the same label semantics; TRAIN imports REAL batches the same way as SIM
  batches (see [training.md](training.md); no repo script names `real-out` or `realapps`, so the exact import path
  is unverified). Gold rows train the student/teacher; unlabeled rows get teacher labels (per NEEDS/HANDOFF; not
  in code here). `real_eval.jsonl` rows keep their original split, and `evalset.py` reads `test,dev,train` unless
  `--splits` narrows it, so an eval row can also be a row of some batch's `train.jsonl` (whether TRAIN excludes
  eval ids is unverified).
- `meta` fields beyond the row: `source = "realapps"`, `seed`, `app`, `framework`, `libs`, `integration`, `domain`,
  `program_family`, `family`, `patterns`, `chaos`, `clean`, `budget`, `runtime`, `browser = "chromium-headless"`,
  `oss`; decision rows add `trigger`, `decision`, `t`, `explored_before`, `best`, `passive_best`, `passive`,
  `costs`, `cost_futures`, `futures`, `adjusted`, `se`, `non_passive_mass`, `cost_parts`, `tiers`, `diagnosis`,
  `diag_why`, `diag_trace`, `subject`, `transform`; ask rows add `kinds`; unlabeled rows add `unlabeled`,
  `base_choice`; diagnosis-only rows add `diagnosis_only`.
- **Eval set** (`realapps/scripts/evalset.py <dirs> --out <dir> [--splits test,dev]`; default splits
  `test,dev,train`): cases `stale-overwrite`, `duplicate-submit`, `clean-benign`, `benign-salient`, `genuine-break`,
  each with `meta.eval_case` and `meta.eval_expect`, capped per case (`--per-case`, default 2000), original split
  kept. It keeps its own `PASSIVE` copy (includes `delivery`).

### The never-worse and determinism sweeps (`realapps/src/harness/debug.ts`)

- `--det A-B [--app a,b]`: per seed and app, an ideal run (for the pins) then the base run twice with the
  scenario's exploration; identical iff both runs are `ok` and decision `fp`s, snapshots, network log and server
  state hash equal. Prints `determinism: n/N identical` (no `--clean` option here).
- `--interference A-B [--clean] [--app ...]`: per seed and app, an ideal run (for the pins), then the same scenario
  with `mode: "observe"` and with
  `mode: "heal"` under the all-passive base decider (no forced actions, explore 0); compares final DOM and server
  content. Prints `interference: x/N runs changed by GenClass with an all-passive model`. This is the runtime's
  "never make a correct app worse" check cited in `docs/runtime/RESULTS.md` §4 and `packages/runtime/STATUS.md`.
- Single-scenario modes (`--app`, `--seed`, `--clean`): default (ideal + base summary, triggers, diagnoses, network
  correlation), `--twice`, `--traj` (runs `generateTrajectory` with `testKeep: 1`), `--show N`, `--steps`,
  `--dom-at t1,t2`, `--force K:action` (DOM over time: ideal vs base vs forced), `--mode <mode>` for the base run.

## Invariants and gotchas

- **Never read `demos/`** from `realapps/` (independent evaluation; `HANDOFF.md`). No realapps code references it.
- **Flag order matters:** the first option of every `variants` entry is the correct/guarded default; clean runs use
  only first options. Adding a buggy option first silently corrupts the clean-benign eval case and false-intervention
  numbers.
- **Determinism is the contract.** Anything on real time breaks the prefix check: `IntersectionObserver`/
  `ResizeObserver` logic, CSS transition/animation events, full page reloads, IndexedDB, FileReader, Workers,
  BroadcastChannel, EventSource, image/font gating, code splitting (`apps/README.md`). Run `--det` after any app
  or world change.
- **Pin the runtime for data.** A `working-tree` build stamps `meta.runtime = "working-tree"`; production data must
  be built from a `git archive` of a frozen tag (`situation-v2` = 6e5e86e). Rows from different runtime tags must not
  be mixed: v1 pilot rows (`pilot4`, `pilot-all`) do not match the v2 situation format.
- **realapps depends on sim source by relative import** (`sim/src/oracle/cost.js`, `sim/src/rng.js`,
  `sim/src/run/transform.js`, `sim/src/ask/questions.js`; vocabulary mirrored from `sim/src/world/scenario.ts`).
  A change there changes realapps labels without touching `realapps/`. `cluster.sh sync` therefore rsyncs `sim/`
  and `packages/runtime/` too.
- **Passive actions come from the bundled runtime's `PASSIVE`;** a trigger missing there (or mapped to `""`, as
  `ask` is) falls back to the first offered action. `realapps/scripts/analyze.py` and `evalset.py` keep their own
  copies of the map (both include `delivery`); update them if the runtime's map changes.
- **Secret-word redaction:** `apps/README.md` says not to name a store `auth` (use `session`). At b435acb the
  runtime (`packages/runtime/src/util.ts` -> `isSensitivePath`) judges object fields by their leaf name, so
  `auth.loading` or `auth.user.name` survive and only secret leaves (`auth.token`, `form.password`) or opaque
  credential-like strings under `auth`/`session`/`cookie` are redacted; a string or number atom named `auth` is
  still redacted whole. Keep following the guide's advice.
- **The ideal run's `ALL_OFF` (`src/world/index.ts`) and the other runs' `OBSERVE` (`trajectory.ts`) predate the v2
  `eventsource` observer** (neither lists it, so the
  runtime's default "on" applies). It never installs because `netapi.ts` sets `window.EventSource = undefined`;
  apps must not use EventSource anyway (`apps/README.md`).
- **Outputs never go under `~/gcl/<slot>`:** `scripts/vm.sh` syncs slots with `--delete`. Use `~/gcl/real-out/`.
- **The DOM term is coarse** (line multisets): an empty page and a page with different data can look alike. Store
  weights and blocked intents carry most of the signal for store apps.
- **Observe-only OSS apps weigh the DOM ×2 via their own manifests** (each of the 12 sets `domWeight: 2`;
  `conduitManifest` does not, so the two store-integrated OSS Conduits use 1); the jQuery and `superagent-fleet`
  observe-only apps do not set it and use 1, although the README says 2 for all observe-only apps.
- **Ideal runs are blind but installed:** observe mode, every observer off, no decider. Do not turn observers on
  there; the ideal must not depend on the runtime.
- **`debug.js --interference` compares explicit modes**, so it is unaffected by the library's default mode. Its
  "heal" leg uses the probe decider, which answers passive when nothing is forced and ε = 0.

## How to change it safely

- **Add an app:** follow `realapps/apps/README.md` (manifest + source under `apps/<name>/`, integration via
  `apps/_shared/genclass.ts`, flags with correct-first options, weights for error/loading/input fields, relations for
  derived values). Then (with the user's OK, on a VM or a machine with Chromium): `node build.mjs <name>`,
  `node dist/harness/debug.js --app <name> --seed 1 --show 1 --twice --steps` for seeds 1–6 (ideal/base `ok=true`,
  network correlated N/N, `first diff -1`), and `--traj` (no drops). Decide whether it belongs in a test-only list.
- **Change the harness (world, cost, labels, scenario):** rerun `--det 1-3` and `--interference 1-3 --clean` over
  all apps and a short pilot plus `analyze.py`; compare passive-best shares with the previous batch. Never change
  label semantics in a way that diverges from `sim/src/oracle/cost.ts` without changing SIM too: the two sources are
  trained together.
- **Runtime changed (new tag):** export the tag (`TAG=<tag> realapps/scripts/cluster.sh sync|setup <host>`),
  rebuild, rerun determinism and interference sweeps and a pilot, re-audit `EXAMPLES.md`, and fix the hard-coded
  `runtime` string in `gen.ts` -> `manifest`.
- **Generate:** `TAG=situation-v2 realapps/scripts/cluster.sh setup <host>`, then
  `realapps/scripts/cluster.sh run <host> <batch> <first seed> <trajectories> [workers] [extra gen args]`, `status`,
  `stop`, and deallocate the node. Use disjoint seed ranges per batch (1,000,000 apart). All of this is Azure work:
  **ask the user first**, and remember the colleague is operating the cluster (c01, c10, c11 are REAL's).
- **Typecheck:** there is no `realapps/tsconfig.json` and realapps is not a root workspace, so `npm run typecheck`
  and CI do not cover it; esbuild strips types without checking. Review type changes by reading.

## Tests

- **No unit tests and no CI coverage.** `realapps/` has no `test/` directory; `.github/workflows/ci.yml` builds and
  tests `@genclass/runtime` only.
- Quality gates are the sweeps, run on a VM with Chromium (none run by us; all need the user's OK):
  - determinism: `node dist/harness/debug.js --det 1-5 [--app a,b]`;
  - never worse: `node dist/harness/debug.js --interference 1-3 --clean` (and without `--clean` for chaos);
  - prefix check: `drops["prefix-mismatch"]` in `stats.json` should be 0;
  - per-row audit: `python3 realapps/scripts/examples.py <dir> ...` (as in `EXAMPLES.md`).
- The runtime side has a regression test derived from this harness's v1 finding:
  `packages/runtime/test/no-reorder.test.ts` (the realworld promise middleware through `genclassEnhancer` gives the
  same dispatches and state in guard/heal as in observe).
- Recorded results:
  - v1 pilot `pilot-all` (README, NEEDS 15): 500 trajectories, 66 apps, 3,403 gold + 3,789 unlabeled, 0 drops;
    determinism 198/198; interference 4/198 clean runs changed (2 apps); eval set 366 rows.
  - v1 `pilot4`: 230 trajectories, 26 apps, 1,654 gold + 2,325 unlabeled; audited in `EXAMPLES.md`; eval 213 rows.
  - v2 (NEEDS 16): determinism 132/132, interference 0/132; `v2-pilot` 400 trajectories, 2,519 gold (135 `delivery`),

  - v2 runtime batch 5 (STATUS.md): all 66 apps, seeds 1–6, clean: 0/396 changed; chaos seeds 1–3: 3/198 changed

- **`gen.ts` -> `manifest` hard-codes `runtime: "situation-v1 (packages/runtime/src bundled from source)"`.** v2
  batch `manifest.json` files therefore say situation-v1. The per-row `meta.runtime` is correct (read from
  `dist/runtime-tag.txt`). Trust `meta.runtime`.
- **README is half v1:** the "Pilot" and "Runtime findings" sections, `EXAMPLES.md` and the `Run it` example
  (`RW_RUNTIME_TAG=situation-v1`) describe situation-v1; the v2 results live only in `training/NEEDS.md` 16 and
