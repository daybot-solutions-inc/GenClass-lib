# Glossary

> **Scope:** every term defined in the subsystem docs under `docs/agents/`, the shared runtime vocabulary (op, trigger, situation, hold, tier, delivery, ...) and project jargon (workstreams, datasets, label rules S1/S2/T1, training stages and the teacher/distillation/DAgger pipeline, hosts, model names, benchmark names, the realapps sweeps). One alphabetical list. A qualifier in parentheses separates words that mean different things in different subsystems, e.g. *chaos (demos)* vs *chaos (sim)*, *Decision (runtime)* vs *Decision (extension)*, *S1 (fact)* vs *S1 (sim label rule)*.
> **Read this when:** a doc, a status file or the code uses a word you do not know, or two docs seem to use one word differently.
> **Source of truth:** the code. Verified against branch `mvp-v2-merge` at f107013 (`mvp-v2` + origin/runtime eff18cb merged + two runtime fixes), 2026-10-08. Entries untouched by the merge keep their b435acb wording where nothing changed. If this doc and the code disagree, the code wins.

Conventions: **Code:** `path/from/repo/root` -> `symbol` (a method is written `Class.method`). **Doc:** the subsystem doc with the full detail. "See *x*" points to another entry of this glossary. Runtime numbers (thresholds, budgets, sizes) are the defaults at f107013 (unchanged since b435acb). Fact ids: the runtime's own fact ids (M2, R3, F1 for "failure", S1 for "stall", ...) predate batch 5 and collide with the batch-5 evidence facts **F1–F9** (named after `sim/SEPARABILITY.md` §6) and with SIM's label rules **S1/S2**; the qualifier in each entry says which is meant.

## A

- **A/A noise (demos)**: Bug-verdict flips between two Off runs of the same seeds; the noise floor against which *fixed / introduced* counts are read (board demo: 1 of 30 after common random numbers). Doc: [demos](demos.md).
- **action**: The model's answer to the `action` question: one of the actions offered for the trigger, built-ins first (passive first, then the applicable guard/heal actions), then applicable custom actions. The `action` question is asked only when at least 2 actions apply; with one, the runtime treats the answer as `{ <passive>: 1 }`. See *built-in actions*. Code: `packages/runtime/src/situation/questions.ts` -> `TRIGGER_ACTIONS`, `buildQuestions`; `packages/runtime/src/situation/build.ts` -> `builtinApplicable`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **actionLabel (sim)**: The sim's soft `action` label from counterfactual costs: each action's per-future cost gets a tier premium (or the tie rule), then `p_a ∝ exp(−gap_a / τ_a)`, where `gap_a` is the mean paired cost difference to the best action and `τ_a = 0.10 + 1.0 × SE` of that difference. Code: `sim/src/oracle/cost.ts` -> `actionLabel`, `LABEL`. Doc: [sim](sim.md), [model-io-contract](model-io-contract.md).
- **ActionRecord**: The record `a<n>` of one non-passive action attempt (built-in, custom or late revert), kept also when it failed (`ok: false`): `decisionId, action, tier, trigger, subject, at, ok, error?, changed, undo?, late?`, plus `dropped?` (delivery `discard`: the paths dropped so far, growing while the 10 s discard mark lasts). Fires the `act` event; `rt.interventions()` returns the last 200. Also called an *intervention*. Code: `packages/runtime/src/types.ts` -> `ActionRecord`; `packages/runtime/src/runtime.ts` -> `RuntimeImpl.onDecision`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **adapter (store kind)**: A store whose value lives in a state library; writes commit through the proposal's `commit(next)`, and GenClass may write directly (rollback, revert) only when `AdapterIO.set` exists (`writable`). The Redux enhancer and the Zustand middleware create adapter stores. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.adapter`; `packages/runtime/src/types.ts` -> `AdapterIO`, `AdapterHandle`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **adapters (framework)**: Subpath exports owned by UI: `@genclass/runtime/react` (`GenClassProvider`, `useGenClass`, `useGenClassState`, which registers an atom, plus decision/status hooks), `@genclass/runtime/redux` (`genclassEnhancer`) and `@genclass/runtime/zustand` (`genclass` middleware). Code: `packages/runtime/src/adapters/react.ts` -> `useGenClassState`; `packages/runtime/src/adapters/redux.ts` -> `genclassEnhancer`; `packages/runtime/src/adapters/zustand.ts` -> `genclass`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **ambient op**: The op whose work is running now (`Context.cur`). `startOp` uses it as the `cause` of new ops and the hub records it as the writer of state writes. `Context.run` sets it synchronously, `Context.stick` until the end of the macrotask; GenClass does not propagate it through arbitrary promises. Code: `packages/runtime/src/trace/context.ts` -> `Context`. Doc: [observe-and-trace](runtime/observe-and-trace.md).
- **answer cache**: The `DeciderQueue` cache of provider answers keyed by `fnv1a(trigger + state + questions)` (subject and priority excluded): 64 entries, 30 s TTL, served only while the provider is `ready`, with no latency sample. Code: `packages/runtime/src/decide/decider.ts` -> `DeciderQueue`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **apply (action)**: Passive action of the `mutation` trigger: keep the write. By default (`holdWrites` off) the write has already applied when the non-blocking `mutation` trigger is decided, so `apply` changes nothing; with `policy.holdWrites: true` it lets the held write update the state (or when the store's queue drains). Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.observeWrite`, `RuntimeImpl.gateMutation`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **ask (trigger)**: The developer-question trigger. `rt.ask(question, { about, timeoutMs })`, `rt.decide(question, options)` and `rt.situation()` build an `ask` situation about now, an op id or a store outside `trigger()`: no triage, no gate, no `Decision`, queue priority 1. `rt.ask` replaces the questions with `{ answer: q }`. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.ask`, `RuntimeImpl.decide`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md), [learn-situation-triage](runtime/learn-situation-triage.md).
- **ask row / ask probe (sim)**: At `scenario.askTimes` the base run calls `runtime.situation("ask")` (side-effect free) and records it; `askQuestions` attaches 1–3 programmatic questions with exact labels (`q_*` qids). Code: `sim/src/ask/questions.ts` -> `askQuestions`. Doc: [sim](sim.md).
- **assetBase (script-tag build)**: Where the script-tag build loads its other files (model worker, ORT chunks, devtools): for a jsDelivr or unpkg URL of `@genclass/runtime` (any version or none) the same CDN pinned to the version baked in at build time (`@<__GENCLASS_VERSION__>/dist/`), else the script file's own directory, else jsDelivr at that version. Because the version comes from `package.json`, building this tree before the version bump points it at the published alpha.1, which has no `dist/cdn/`. Code: `packages/runtime/src/cdn/global.ts` -> `assetBase`. Doc: [status-and-known-issues](status-and-known-issues.md).
- **atom (store kind)**: A store whose value GenClass owns (`StoreRec.value`), created by `rt.atom(name, initial, opts)` and by the React hook `useGenClassState`; always writable. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.atom`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **attempt (model load)**: `LoadAttempt { variant, device, error }`: a load plan that failed, listed in `status.attempts`. Code: `packages/runtime/src/model/errors.ts` -> `LoadAttempt`. Doc: [model-host](runtime/model-host.md).
- **auto budget**: See *situation budget*.
- **auto entry (`@genclass/runtime/auto`)**: Zero-code setup (INSTALL, f3a9dd1; not in the published `0.1.0-alpha.1`): `import "@genclass/runtime/auto"` as the first import of the entry file calls `startAuto()`, which merges `<meta name="genclass">` and `window.GENCLASS_CONFIG` and calls `GenClass.init` (devtools if asked). With no mode it runs the runtime default, **observe** on this branch; `/auto/observe`, `/auto/guard` and `/auto/heal` pass that mode. The default export is the runtime. Outside a browser it is the inert runtime. Kept by bundlers through `sideEffects`. Code: `packages/runtime/src/auto.ts`; `packages/runtime/src/cdn/auto-start.ts` -> `startAuto`; `packages/runtime/src/cdn/auto-{observe,guard,heal}.ts`. Doc: [status-and-known-issues](status-and-known-issues.md).

## B

- **backfill (devtools)**: At mount the overlay replays `decisions(200)`, `interventions(200)` and `history(400)`, and re-derives detections with the literal 0.6 threshold; report sentences are not available for these items. Code: `packages/runtime/src/devtools/index.ts` -> `mountDevtools`. Doc: [devtools](runtime/devtools.md).
- **background delivery decision**: A delivery that cannot be held (`RuntimeImpl.deliveryHoldable` false: observe mode, paused, model not `ready`, no permitted non-passive delivery action, or the model too slow for the hold budget) is released synchronously, before its body is read, and still decided in the background (054da38): an in-memory body (XHR, WebSocket, EventSource) is analysed before the app's listeners run; a fetch body is analysed until `BODY_WAIT_MS` or until its chain's first write (`RuntimeImpl.finalizeDeliveries`). The decision is recorded and reported with `executed: false` and answers delivery standing questions; while it is pending it covers its chain's predicted writes (no second mutation decision). In guard or heal with a too-slow model, the chain's writes keep their own decisions and late revert instead (`RuntimeImpl.writesCanAct`). Fixes review findings DL-3 and DL-4. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.runDelivery`, `deliveryHoldable`, `finalizeDeliveries`, `covered`; test `packages/runtime/test/observe-delivery.test.ts`. Doc: [status-and-known-issues](status-and-known-issues.md).
- **BandedEncoder**: See *tree layout / BandedEncoder*.
- **base run (sim)**: The scenario run with the real runtime, a recording decider, exploration (ε of 0, 0.08 or 0.2, weighted 4/3/2; ε where the sim sees a problem, ε/4 elsewhere) and ask probes. Its recorded decisions are the candidate decision points. Code: `sim/src/run/runner.ts` -> `runScenario`; `sim/src/gen/trajectory.ts` -> `generateTrajectory`. Doc: [sim](sim.md).
- **baseline**: Online statistics per op signature, for fetch/XHR ops only (not synthetic, not GenClass): last 64 non-failure latencies (nearest-rank median/p95, need ≥ 5 samples), last 20 outcomes, failure streak, an EWMA error rate (computed but never read), last 128 start times (recent vs usual rate), and per request identity an EWMA gap between identical requests. Memory only; feeds facts, stats lines, the stall timer and `delay` backoff. Code: `packages/runtime/src/learn/baselines.ts` -> `Baselines`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **batch (CORE)**: A numbered CORE release of runtime changes, recorded in `packages/runtime/STATUS.md`. Batch 1 = SIM requests 1–5; batch 2 = situation budget, `sectionLimits`, auto hold budget, late revert, provider errors fail open; batch 3 = REVIEW's 34 findings, SIM a–f, summed-mass gate, `transient`, compact questions (commit 1a77558, tagged `situation-v1`); *batch 4* and *batch 5* (see their entries) make situation-v2. Doc: [status-and-known-issues](status-and-known-issues.md).
- **batch 4**: Runtime batch fcd1e68, "decide at the network boundary, never reorder app writes": the new *delivery* trigger (fetch/XHR responses, WebSocket and the new EventSource observer), store writes no longer held by default (`policy.holdWrites` opt-in; a salient write raises a non-blocking `mutation` that only a *late revert* can enforce), *covered writes*, version *conflicts* (`situation/conflicts.ts`), the `observe.untrustedEvents` option, `STATE_CHAR_BUDGET` 3,200 → 2,400. Motivated by the demos, where holding store writes made correct apps worse (board jump-backs, overwritten keystrokes, search latency). Doc: [decide-policy-actions](runtime/decide-policy-actions.md), [learn-situation-triage](runtime/learn-situation-triage.md).
- **batch 5**: Runtime batch "separability facts, real-app text fixes; freeze situation-v2" (commit 6e5e86e, tagged `situation-v2`): the evidence facts *F1–F9* and read-your-writes (`situation/content.ts`, `situation/evidence.ts`, `learn/cadence.ts`), stricter delivery salience, relation-quality rules and count-by-group invariants (F8), `UserAction.clicks`. Part of it landed earlier inside the realapps commit fcb8189: `situation/content.ts` (F1–F3), diff-centred string previews (`state/fields.ts` -> `stringDiff`), leaf-based redaction (`util.ts` -> `isSensitivePath`) and DOM-observer fixes (shadow DOM, nested labels). Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **benchmax**: Campaign to beat every published Jev number through each publisher's own harness: 549 targets (154 headline/counted), tracks Z and S, 19 registered adapter specs; no test-split scoreboard exists in the repo. Code: `jev_local/bench/benchmax/__init__.py` -> `Spec`; `scripts/benchmax.py`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md).
- **block (action)**: Heal-tier `request` action: do not send; answer with a 503 `Response` (statusText `Blocked by GenClass`, header `x-genclass: blocked`) and end the op `blocked` (XHR: a faked 503). Code: `packages/runtime/src/observe/fetch.ts` -> `installFetch`; `packages/runtime/src/observe/cache.ts` -> `blockedResponse`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **branch (packing)**: State + one question header + one of its items. Positions restart per branch (header at `S..`, every item at `S + len(header)..`). In the runtime TS packer `meta.max_len` (default 1536) bounds the state plus the longest branch and `meta.max_total` (8192) the whole sequence; `FastEngine` also bounds positions and splits the rest into passes. The Python `Packer.pack` bounds the total sequence by `max_len` (default 2048) and the trainer's `Packer.pack_split` bounds state + whole question blocks per sequence. Code: `packages/runtime/src/model/packer.ts` -> `Packer`; `jev_local/engine/encoder/tokenize_pack.py` -> `Packer.pack`, `Packer.pack_split`; `jev_local/engine/encoder/engine.py` -> `plan_passes`. Doc: [model-io-contract](model-io-contract.md), [genclass-model-lineage](genclass-model-lineage.md).
- **browserClock**: The default `Clock`: `performance.now()` (or a counter), with `setTimeout`, `clearTimeout`, `setImmediate`, `MessageChannel` and `performance` captured at module load so the runtime's own timers never pass through its timers observer; `afterTask` runs via `setImmediate` (Node) or `MessageChannel`. Code: `packages/runtime/src/clock.ts` -> `browserClock`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **bucket (training mixture)**: A mixture group named after the parent directory of a shard file (`data/s3/simA/shard07.jsonl` -> `simA`). Weights in `mix_*.json` are renormalised over the buckets present, so a missing bucket is silently dropped. Code: `jev_local/train/stream.py` -> `_names`, `MixConfig`. Doc: [training](training.md).
- **budget**: Overloaded word; check which one is meant: *situation budget* (characters of situation text), *hold budget* (ms a subject may be held), *budget scale* (shrink factor of the auto situation budget), the packer's token limits `max_len` / `max_total` (see *max_tokens_exceeded*), *pass / pass_tokens* (training tokens per mixture draw) and *budget (sim)*.
- **budget (sim)**: The `situation.budget` the sim passes to the runtime per scenario: 3200, 2000 or 1000 characters (weights 40/30/30), recorded in `meta.budget`. These are still the situation-v1 device budgets: the v2 runtime's full budget is 2,400 and its auto budgets are 2,400 / 2,000 / 1,667 / 1,333 / 1,000, so about 40% of v2 sim rows use a size production never produces (open review finding; realapps samples the same 3,200 / 2,000 / 1,000). Code: `sim/src/world/scenario.ts` -> `buildScenario`. Doc: [sim](sim.md).
- **budget scale**: `RuntimeImpl.budgetScale`: starts at 1 and is multiplied by 0.8 (floor 0.5, never restored) each time the provider fails with `max_tokens_exceeded`; it applies only to the automatic situation budget. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.situationBudget`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **built-in actions**: The 15 generic actions in `BUILTIN_ACTIONS` (name, tier, model-facing description), offered per trigger by `TRIGGER_ACTIONS` and applicability: passive `apply`, `send`, `deliver`, `wait`, `ignore`; guard `discard`, `defer`, `coalesce`, `delay`; heal `block`, `serve_cached`, `retry`, `hedge`, `rollback`, `resync`. `delivery` reuses `deliver`, `discard` and `defer` with its own descriptions. Each has its own entry here. Code: `packages/runtime/src/situation/questions.ts` -> `BUILTIN_ACTIONS`, `TRIGGER_ACTIONS`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **bypass write**: A write applied at once in the caller's stack without any trigger: user-sync writes, writes from GenClass ops, stores registered with `hold: false`, writes while gating is off (paused or destroyed), no-op writes and unholdable writes. Errors propagate to the caller. Since batch 4 every write applies at once by default anyway; the difference is that only a non-bypassed write may raise a non-blocking `mutation` trigger. Every non-GenClass write, bypassed or not, first passes the delivery drop filter (`StoreHub.propose`). Code: `packages/runtime/src/state/hub.ts` -> `StoreHub`. Doc: [state-and-adapters](runtime/state-and-adapters.md).

## C

- **c01 / c02–c23**: Azure F80 hosts (`vm-jev-c01`…`c23` in resource group `rg-jev-train`). `c01` (10.0.0.6) is TRAIN's workbench and data hub (prune, generate, eval, export); `c02`–`c11` were the round-1 training nodes (`c02` R32 rank 0, `c09` R17 rank 0); `c12`–`c23` were added on 2026-10-08 by `training/cluster_expand.sh`. SIM's v2 generation is done (its 20 nodes were deallocated 04:55–05:10 UTC); per the `training/NEEDS.md` claim table at eff18cb, TRAIN holds c02 (v2 workbench), c03–c09 and c13 (*r17-v2a*) and c12 and c14–c23 (*t150-v2a*), and REAL runs `v2c1`..`v2c4` on c01, c10, c11 and `data`. Nobody on our side touches Azure. The host table lives in `~/.jev-local/azure_hosts` (not in the repo). See *train VM*. Doc: [training](training.md), [sim](sim.md), [realapps](realapps.md).
- **cadence (F6)**: What the runtime learned about when a request signature is sent: `periodic { period, intervals, last, next }` (a schedule: requests not caused by user actions, ≥ 4 runs, ≥ 75% of intervals within ±25%, dropped after 3 missed periods) or `debounced { delay, matching, of }` (sent a fixed delay after the user's last input, from timers started by user actions). Stated by fact F6 ("GET /api/feed runs on a schedule: every 1.00s …; the next run is due in 0.95s."), always neutral; it tells the model whether a stale value will heal by itself. Code: `packages/runtime/src/learn/cadence.ts` -> `Cadence`, `CadenceInfo`; `packages/runtime/src/situation/evidence.ts` -> `cadenceFact`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **calibration / calibration.json**: Post-hoc temperature scaling of raw logits read from `calibration.json`: τ by header key, else by `(kind, K-bucket)`, else `τ(K) = a + b·ln K` clamped to `[0.5, 5.0]`, else per kind; a noul uses its header temperature, else a Platt affine, else the per-kind temperature. Trained checkpoints ship all-1.0 temperatures; the real file comes from `training/eval_runtime.py --write-calibration`. Code: `packages/runtime/src/model/calibrate.ts` -> `tauFor`, `noulAffine`, `calibrateLogits`; `jev_local/engine/encoder/calibrate.py` -> `tau_for`. Doc: [model-host](runtime/model-host.md), [genclass-model-lineage](genclass-model-lineage.md).
- **candidate**: See *permitted set / candidate / mass*.
- **cause / root (op)**: `OpRec.cause` is the id of the op that was ambient (or passed explicitly) when the op started; `root` is the cause's root, or the op's own id when it has no cause. User ops and WS messages are always roots; a retry or hedge op names the original op as its cause. Code: `packages/runtime/src/trace/ops.ts` -> `OpRegistry`. Doc: [observe-and-trace](runtime/observe-and-trace.md).
- **CDN script tag / global build**: `dist/genclass.global.min.js` (and the unminified `.global.js`), an IIFE built from `packages/runtime/src/cdn/global.ts` by `tsup.config.ts` -> `globalBuild` (INSTALL, f3a9dd1; not in the published `0.1.0-alpha.1`). Put first in `<head>`, it calls `GenClass.init()` with options from its `data-*` attributes, the meta tag and `window.GENCLASS_CONFIG`, exposes `window.GenClass`, and loads the model worker (`dist/cdn/worker.js`, from a same-origin Blob URL), onnxruntime-web (`dist/cdn/ort-*.js`) and the devtools on demand from *assetBase*. Without `data-mode` it runs the runtime default (observe here). `init` writes a pinned jsDelivr tag with *SRI* for plain-HTML projects. Doc: [status-and-known-issues](status-and-known-issues.md).
- **chain**: An op and its causal descendants (ops sharing its `root`). In facts, "same chain" means one op is an ancestor-or-self of the other; "the op's chain wrote" (`RuntimeImpl.chainWrites`) means fields written by the op's root chain since the root started. Code: `packages/runtime/src/situation/facts.ts` -> `computeFacts`; `packages/runtime/src/runtime.ts` -> `RuntimeImpl.chainWrites`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **chain keys (normalised)**: Keys of `OpRec.chain`: field paths passed through `normalizeFieldPath`, which turns every segment after the store name that is id-like or contains a digit into `:id` (`chat.byId.m21` -> `chat.byId.:id`). Transition shapes, involved fields and transition `SubjectRef.paths` use them. Code: `packages/runtime/src/util.ts` -> `normalizeFieldPath`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **chain revert**: The `rollback` implementation for `transition` and `error` triggers: restore exactly the fields the op's root chain wrote (not overwritten since, with a known earlier value, in a writable store) to their values before the chain's first write; undo restores the replaced values. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.revertChain`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md), [state-and-adapters](runtime/state-and-adapters.md).
- **chain write**: `ChainWrite { kind, len0, len1 }`, accumulated per normalised path in `OpRec.chain` of profiled ops (the writer plus up to 8 ancestors) by `RuntimeImpl.onApplied`; the input to transition profiles. `ChainWriteInfo` (`SitEnv.chainWrites`) is the real-path view used by facts and rollback applicability. Code: `packages/runtime/src/trace/ops.ts` -> `ChainWrite`; `packages/runtime/src/runtime.ts` -> `RuntimeImpl.onApplied`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **CHANGELOG.md**: `packages/runtime/CHANGELOG.md` (f3a9dd1). Its `## 0.1.0-alpha.1` section lists the one-command install, `/auto` and the script tag, which the published alpha.1 (806a296) does not contain; those bullets belong to the *next release*. Doc: [status-and-known-issues](status-and-known-issues.md).
- **chaos (demos)**: `RouteChaos` knobs (latency, jitter, failRate, commitFailRate, timeoutRate, hangMs, spikeRate, spikeFactor, reorder, outage, offline) plus per-route overrides, applied by the Service Worker mock server; environment only, never app logic. Clean trials use `CLEAN_CHAOS` (45 ± 15 ms, no failures). Code: `demos/src/shared/chaos.ts` -> `RouteChaos`, `resolveChaos`; `demos/src/shared/scenario-kit.ts` -> `CLEAN_CHAOS`. Doc: [demos](demos.md).
- **chaos (sim)**: Per-scenario network regime `calm | normal | flaky | degraded | storm | mobile | peak | deploy` (weights 2/3/3/3/1/1/1/1; the last three, added in round 2, start from the flaky/degraded/normal base and add their own conditions) that `makeNet` turns into latency multipliers, transient and network-error rates, outages, slow periods, capacity, rate limits, replica lag and server bugs. Code: `sim/src/world/scenario.ts` -> `buildScenario`, `makeNet`. Doc: [sim](sim.md).
- **chaos trial / clean trial (demos)**: A chaos trial randomises chaos and stresses the simulated user, and measures bug rate; a clean trial uses a calm network and a calm user on which the app is correct, so any executed non-passive action is a *false intervention*. Doc: [demos](demos.md).
- **choice (question kind)**: A typed question answered by a softmax over 2–255 labels (`criteria`: label -> description or `null`); the answer is `{ choice, confidence, probabilities }` with probabilities in criteria order. `diagnosis` and `action` are choice questions; `rt.decide()` is a choice shortcut. Code: `packages/runtime/src/types.ts` -> `Question`, `ChoiceAnswer`; `jev_local/schema.py` -> `ChoiceQuestion`. Doc: [model-io-contract](model-io-contract.md), [genclass-model-lineage](genclass-model-lineage.md).

## W

- **W1–W11**: Engine and wire requirements for benchmax runs from `docs/benchmax-research/suite-reproduction-specs.md` §1.2 (e.g. W1 choice = argmax of unrounded probabilities with ties to the first key, W2 score fields, W3 precision, W4 refusal bodies, W5 overflow refuse/truncate, W9 one global calibration file, W10 model id never `jev-*`, W11 determinism). Code: `jev_local/bench/benchmax/runner.py` -> `check_model_id`; `jev_local/api.py` -> `ServeConfig`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md), [genclass-model-lineage](genclass-model-lineage.md).
- **wait (action)**: Passive action of the `stall` trigger: keep waiting for the response. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **waits**: In `RuntimeImpl.trigger`: `opts.hold`, at least one non-passive action permitted by mode and policy, not paused, and (since batch 4) the expected model latency fits the hold budget (`expectedLatency() <= holdBudgetMs()`): whether the subject is actually held. A holdable trigger that does not wait runs its passive action at once and is decided in the background (detection only, `BACKGROUND_DEADLINE_MS` 5 s), which is what every trigger does in the default `observe` mode. For a delivery, `RuntimeImpl.runDelivery` checks the same conditions up front (`deliveryHoldable`, 054da38) and releases a delivery that will not wait before reading its body. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.trigger`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **warm-up**: One forward pass (two on WebGPU) over `WARMUP_STATE` / `WARMUP_QUESTIONS` before a plan is accepted; it sets `status.warmupMs` (which seeds the auto hold budget) and seeds `status.latency`. Code: `packages/runtime/src/model/backend.ts` -> `ModelBackend`, `WARMUP_STATE`. Doc: [model-host](runtime/model-host.md).
- **wire request**: `{ state, questions }`, the only part of `EvaluateRequest` the model host uses; `trigger`, `subject`, `priority` and `timeoutMs` are scheduling and test metadata that never reach the packer. Code: `packages/runtime/src/model/protocol.ts` -> `ToWorker`. Doc: [model-io-contract](model-io-contract.md).
- **worker URL pattern**: The literal `new Worker(new URL("./worker.js", import.meta.url), { type: "module" })` in `defaultWorkerFactory` (and the literal `import("onnxruntime-web/webgpu" | "onnxruntime-web/wasm")` calls beside it) that app bundlers recognise; the browser-test build asserts they survive bundling. Code: `packages/runtime/src/model/host.ts` -> `defaultWorkerFactory`. Doc: [build-test-release](runtime/build-test-release.md).
- **workstream**: A team role that owns paths (runtime CONTRACT §1 and §13): lead, CORE, MODEL, UI, SIM, REAL (added with `realapps/`), DEMOS, TRAIN, REVIEW, INSTALL (added with f3a9dd1). The colleague's Claude sessions play all of them; they communicate through `packages/runtime/STATUS.md`, `HANDOFF.md` and per-requester NEEDS files (REAL's requests live in `training/NEEDS.md`); each has its own entry here. Doc: [status-and-known-issues](status-and-known-issues.md).
- **world (demos)**: One mock-server session in the demos' Service Worker, keyed by `live-<demo>-<rand>` or `trial-<demo>-<run>`; it owns state, chaos, request and event logs, SSE streams and timers. The page controls it only via `postMessage`, so GenClass never observes test traffic. Code: `demos/src/server/core.ts` -> `World`. Doc: [demos](demos.md).
