# Glossary

> **Scope:** every term defined in the subsystem docs under `docs/agents/`, the shared runtime vocabulary (op, trigger, situation, hold, tier, ...) and project jargon (workstreams, datasets, training stages, hosts, model names, benchmark names). One alphabetical list. A qualifier in parentheses separates words that mean different things in different subsystems, e.g. *chaos (demos)* vs *chaos (sim)*, *Decision (runtime)* vs *Decision (extension)*.
> **Read this when:** a doc, a status file or the code uses a word you do not know, or two docs seem to use one word differently.
> **Source of truth:** the code. Verified against commit 654d822 (2026-10-07). If this glossary, a subsystem doc and the code disagree, the code wins.

Conventions: **Code:** `path/from/repo/root` -> `symbol` (a method is written `Class.method`). **Doc:** the subsystem doc with the full detail. "See *x*" points to another entry of this glossary. Runtime numbers (thresholds, budgets, sizes) are the defaults at 654d822.

## A

- **A/A noise (demos)**: Bug-verdict flips between two Off runs of the same seeds; the noise floor against which *fixed / introduced* counts are read (board demo: 1 of 30 after common random numbers). Doc: [demos](demos.md).
- **action**: The model's answer to the `action` question: one of the actions offered for the trigger, built-ins first (passive first, then the applicable guard/heal actions), then applicable custom actions. The `action` question is asked only when at least 2 actions apply; with one, the runtime treats the answer as `{ <passive>: 1 }`. See *built-in actions*. Code: `packages/runtime/src/situation/questions.ts` -> `TRIGGER_ACTIONS`, `buildQuestions`; `packages/runtime/src/situation/build.ts` -> `builtinApplicable`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **actionLabel (sim)**: The sim's soft `action` label from counterfactual costs: each action's per-future cost gets a tier premium (or the tie rule), then `p_a ∝ exp(−gap_a / τ_a)`, where `gap_a` is the mean paired cost difference to the best action and `τ_a = 0.10 + 1.0 × SE` of that difference. Code: `sim/src/oracle/cost.ts` -> `actionLabel`, `LABEL`. Doc: [sim](sim.md), [model-io-contract](model-io-contract.md).
- **ActionRecord**: The record `a<n>` of one non-passive action attempt (built-in, custom or late revert), kept also when it failed (`ok: false`): `decisionId, action, tier, trigger, subject, at, ok, error?, changed, undo?, late?`. Fires the `act` event; `rt.interventions()` returns the last 200. Also called an *intervention*. Code: `packages/runtime/src/types.ts` -> `ActionRecord`; `packages/runtime/src/runtime.ts` -> `RuntimeImpl.onDecision`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **adapter (store kind)**: A store whose value lives in a state library; writes commit through the proposal's `commit(next)`, and GenClass may write directly (rollback, revert) only when `AdapterIO.set` exists (`writable`). The Redux enhancer and the Zustand middleware create adapter stores. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.adapter`; `packages/runtime/src/types.ts` -> `AdapterIO`, `AdapterHandle`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **adapters (framework)**: Subpath exports owned by UI: `@genclass/runtime/react` (`GenClassProvider`, `useGenClass`, `useGenClassState`, which registers an atom, plus decision/status hooks), `@genclass/runtime/redux` (`genclassEnhancer`) and `@genclass/runtime/zustand` (`genclass` middleware). Code: `packages/runtime/src/adapters/react.ts` -> `useGenClassState`; `packages/runtime/src/adapters/redux.ts` -> `genclassEnhancer`; `packages/runtime/src/adapters/zustand.ts` -> `genclass`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **ambient op**: The op whose work is running now (`Context.cur`). `startOp` uses it as the `cause` of new ops and the hub records it as the writer of state writes. `Context.run` sets it synchronously, `Context.stick` until the end of the macrotask; GenClass does not propagate it through arbitrary promises. Code: `packages/runtime/src/trace/context.ts` -> `Context`. Doc: [observe-and-trace](runtime/observe-and-trace.md).
- **answer cache**: The `DeciderQueue` cache of provider answers keyed by `fnv1a(trigger + state + questions)` (subject and priority excluded): 64 entries, 30 s TTL, served only while the provider is `ready`, with no latency sample. Code: `packages/runtime/src/decide/decider.ts` -> `DeciderQueue`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **apply (action)**: Passive action of the `mutation` trigger: let the write update the state now (or when the store's queue drains). Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.gateMutation`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **ask (trigger)**: The developer-question trigger. `rt.ask(question, { about, timeoutMs })`, `rt.decide(question, options)` and `rt.situation()` build an `ask` situation about now, an op id or a store outside `trigger()`: no triage, no gate, no `Decision`, queue priority 1. `rt.ask` replaces the questions with `{ answer: q }`. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.ask`, `RuntimeImpl.decide`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md), [learn-situation-triage](runtime/learn-situation-triage.md).
- **ask row / ask probe (sim)**: At `scenario.askTimes` the base run calls `runtime.situation("ask")` (side-effect free) and records it; `askQuestions` attaches 1–3 programmatic questions with exact labels (`q_*` qids). Code: `sim/src/ask/questions.ts` -> `askQuestions`. Doc: [sim](sim.md).
- **atom (store kind)**: A store whose value GenClass owns (`StoreRec.value`), created by `rt.atom(name, initial, opts)` and by the React hook `useGenClassState`; always writable. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.atom`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **attempt (model load)**: `LoadAttempt { variant, device, error }`: a load plan that failed, listed in `status.attempts`. Code: `packages/runtime/src/model/errors.ts` -> `LoadAttempt`. Doc: [model-host](runtime/model-host.md).
- **auto budget**: See *situation budget*.

## B

- **backfill (devtools)**: At mount the overlay replays `decisions(200)`, `interventions(200)` and `history(400)`, and re-derives detections with the literal 0.6 threshold; report sentences are not available for these items. Code: `packages/runtime/src/devtools/index.ts` -> `mountDevtools`. Doc: [devtools](runtime/devtools.md).
- **BandedEncoder**: See *tree layout / BandedEncoder*.
- **base run (sim)**: The scenario run with the real runtime, a recording decider, exploration (ε of 0, 0.08 or 0.2, weighted 4/3/2; ε where the sim sees a problem, ε/4 elsewhere) and ask probes. Its recorded decisions are the candidate decision points. Code: `sim/src/run/runner.ts` -> `runScenario`; `sim/src/gen/trajectory.ts` -> `generateTrajectory`. Doc: [sim](sim.md).
- **baseline**: Online statistics per op signature, for fetch/XHR ops only (not synthetic, not GenClass): last 64 non-failure latencies (nearest-rank median/p95, need ≥ 5 samples), last 20 outcomes, failure streak, an EWMA error rate (computed but never read), last 128 start times (recent vs usual rate), and per request identity an EWMA gap between identical requests. Memory only; feeds facts, stats lines, the stall timer and `delay` backoff. Code: `packages/runtime/src/learn/baselines.ts` -> `Baselines`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **batch (CORE)**: A numbered CORE release of fixes. Batch 1 = SIM requests 1–5; batch 2 = situation budget, `sectionLimits`, auto hold budget, late revert, provider errors fail open; batch 3 = REVIEW's 34 findings, SIM a–f, summed-mass gate, `transient`, compact questions (commit 1a77558, tagged `situation-v1`). Doc: [status-and-known-issues](status-and-known-issues.md).
- **benchmax**: Campaign to beat every published Jev number through each publisher's own harness: 549 targets (154 headline/counted), tracks Z and S, 19 registered adapter specs; no test-split scoreboard exists in the repo. Code: `jev_local/bench/benchmax/__init__.py` -> `Spec`; `scripts/benchmax.py`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md).
- **block (action)**: Heal-tier `request` action: do not send; answer with a 503 `Response` (statusText `Blocked by GenClass`, header `x-genclass: blocked`) and end the op `blocked` (XHR: a faked 503). Code: `packages/runtime/src/observe/fetch.ts` -> `installFetch`; `packages/runtime/src/observe/cache.ts` -> `blockedResponse`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **branch (packing)**: State + one question header + one of its items. Positions restart per branch (header at `S..`, every item at `S + len(header)..`). In the runtime TS packer `meta.max_len` (default 1536) bounds the state plus the longest branch and `meta.max_total` (8192) the whole sequence; `FastEngine` also bounds positions and splits the rest into passes. The Python `Packer.pack` bounds the total sequence by `max_len` (default 2048) and the trainer's `Packer.pack_split` bounds state + whole question blocks per sequence. Code: `packages/runtime/src/model/packer.ts` -> `Packer`; `jev_local/engine/encoder/tokenize_pack.py` -> `Packer.pack`, `Packer.pack_split`; `jev_local/engine/encoder/engine.py` -> `plan_passes`. Doc: [model-io-contract](model-io-contract.md), [genclass-model-lineage](genclass-model-lineage.md).
- **browserClock**: The default `Clock`: `performance.now()` (or a counter), with `setTimeout`, `clearTimeout`, `setImmediate`, `MessageChannel` and `performance` captured at module load so the runtime's own timers never pass through its timers observer; `afterTask` runs via `setImmediate` (Node) or `MessageChannel`. Code: `packages/runtime/src/clock.ts` -> `browserClock`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **bucket (training mixture)**: A mixture group named after the parent directory of a shard file (`data/s3/simA/shard07.jsonl` -> `simA`). Weights in `mix_*.json` are renormalised over the buckets present, so a missing bucket is silently dropped. Code: `jev_local/train/stream.py` -> `_names`, `MixConfig`. Doc: [training](training.md).
- **budget**: Overloaded word; check which one is meant: *situation budget* (characters of situation text), *hold budget* (ms a subject may be held), *budget scale* (shrink factor of the auto situation budget), the packer's token limits `max_len` / `max_total` (see *max_tokens_exceeded*), *pass / pass_tokens* (training tokens per mixture draw) and *budget (sim)*.
- **budget (sim)**: The `situation.budget` the sim passes to the runtime per scenario: 3200, 2000 or 1000 characters (weights 40/30/30), recorded in `meta.budget`. Code: `sim/src/world/scenario.ts` -> `buildScenario`. Doc: [sim](sim.md).
- **budget scale**: `RuntimeImpl.budgetScale`: starts at 1 and is multiplied by 0.8 (floor 0.5, never restored) each time the provider fails with `max_tokens_exceeded`; it applies only to the automatic situation budget. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.situationBudget`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **built-in actions**: The 15 generic actions in `BUILTIN_ACTIONS` (name, tier, model-facing description), offered per trigger by `TRIGGER_ACTIONS` and applicability: passive `apply`, `send`, `deliver`, `wait`, `ignore`; guard `discard`, `defer`, `coalesce`, `delay`; heal `block`, `serve_cached`, `retry`, `hedge`, `rollback`, `resync`. Each has its own entry here. Code: `packages/runtime/src/situation/questions.ts` -> `BUILTIN_ACTIONS`, `TRIGGER_ACTIONS`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **bypass write**: A write applied at once in the caller's stack without gating: user-sync writes, writes from GenClass ops, stores registered with `hold: false`, writes while gating is off (paused or destroyed), no-op writes and unholdable writes. Errors propagate to the caller. Code: `packages/runtime/src/state/hub.ts` -> `StoreHub`. Doc: [state-and-adapters](runtime/state-and-adapters.md).

## C

- **c01 / c02–c11**: Azure hosts used by TRAIN: `c01` (10.0.0.6) is the workbench and data hub (prune, generate, eval, export); `c02`–`c11` are F80 training nodes (`c02` is R32 rank 0, `c09` is R17 rank 0). The host table lives in `~/.jev-local/azure_hosts` (not in the repo). See *train VM*. Doc: [training](training.md).
- **calibration / calibration.json**: Post-hoc temperature scaling of raw logits read from `calibration.json`: τ by header key, else by `(kind, K-bucket)`, else `τ(K) = a + b·ln K` clamped to `[0.5, 5.0]`, else per kind; a noul uses its header temperature, else a Platt affine, else the per-kind temperature. Trained checkpoints ship all-1.0 temperatures; the real file comes from `training/eval_runtime.py --write-calibration`. Code: `packages/runtime/src/model/calibrate.ts` -> `tauFor`, `noulAffine`, `calibrateLogits`; `jev_local/engine/encoder/calibrate.py` -> `tau_for`. Doc: [model-host](runtime/model-host.md), [genclass-model-lineage](genclass-model-lineage.md).
- **candidate**: See *permitted set / candidate / mass*.
- **cause / root (op)**: `OpRec.cause` is the id of the op that was ambient (or passed explicitly) when the op started; `root` is the cause's root, or the op's own id when it has no cause. User ops and WS messages are always roots; a retry or hedge op names the original op as its cause. Code: `packages/runtime/src/trace/ops.ts` -> `OpRegistry`. Doc: [observe-and-trace](runtime/observe-and-trace.md).
- **chain**: An op and its causal descendants (ops sharing its `root`). In facts, "same chain" means one op is an ancestor-or-self of the other; "the op's chain wrote" (`RuntimeImpl.chainWrites`) means fields written by the op's root chain since the root started. Code: `packages/runtime/src/situation/facts.ts` -> `computeFacts`; `packages/runtime/src/runtime.ts` -> `RuntimeImpl.chainWrites`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **chain keys (normalised)**: Keys of `OpRec.chain`: field paths passed through `normalizeFieldPath`, which turns every segment after the store name that is id-like or contains a digit into `:id` (`chat.byId.m21` -> `chat.byId.:id`). Transition shapes, involved fields and transition `SubjectRef.paths` use them. Code: `packages/runtime/src/util.ts` -> `normalizeFieldPath`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **chain revert**: The `rollback` implementation for `transition` and `error` triggers: restore exactly the fields the op's root chain wrote (not overwritten since, with a known earlier value, in a writable store) to their values before the chain's first write; undo restores the replaced values. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.revertChain`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md), [state-and-adapters](runtime/state-and-adapters.md).
- **chain write**: `ChainWrite { kind, len0, len1 }`, accumulated per normalised path in `OpRec.chain` of profiled ops (the writer plus up to 8 ancestors) by `RuntimeImpl.onApplied`; the input to transition profiles. `ChainWriteInfo` (`SitEnv.chainWrites`) is the real-path view used by facts and rollback applicability. Code: `packages/runtime/src/trace/ops.ts` -> `ChainWrite`; `packages/runtime/src/runtime.ts` -> `RuntimeImpl.onApplied`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **chaos (demos)**: `RouteChaos` knobs (latency, jitter, failRate, commitFailRate, timeoutRate, hangMs, spikeRate, spikeFactor, reorder, outage, offline) plus per-route overrides, applied by the Service Worker mock server; environment only, never app logic. Clean trials use `CLEAN_CHAOS` (45 ± 15 ms, no failures). Code: `demos/src/shared/chaos.ts` -> `RouteChaos`, `resolveChaos`; `demos/src/shared/scenario-kit.ts` -> `CLEAN_CHAOS`. Doc: [demos](demos.md).
- **chaos (sim)**: Per-scenario network regime `calm | normal | flaky | degraded | storm` (weights 2/3/3/3/1) that `makeNet` turns into latency multipliers, transient and network-error rates, outages, slow periods, capacity, rate limits, replica lag and server bugs. Code: `sim/src/world/scenario.ts` -> `buildScenario`, `makeNet`. Doc: [sim](sim.md).
- **chaos trial / clean trial (demos)**: A chaos trial randomises chaos and stresses the simulated user, and measures bug rate; a clean trial uses a calm network and a calm user on which the app is correct, so any executed non-passive action is a *false intervention*. Doc: [demos](demos.md).
- **choice (question kind)**: A typed question answered by a softmax over 2–255 labels (`criteria`: label -> description or `null`); the answer is `{ choice, confidence, probabilities }` with probabilities in criteria order. `diagnosis` and `action` are choice questions; `rt.decide()` is a choice shortcut. Code: `packages/runtime/src/types.ts` -> `Question`, `ChoiceAnswer`; `jev_local/schema.py` -> `ChoiceQuestion`. Doc: [model-io-contract](model-io-contract.md), [genclass-model-lineage](genclass-model-lineage.md).
- **CI**: There is none: the repo has no `.github/` directory; adding CI is open work in `OPEN_TASKS.md`. Doc: [build-test-release](runtime/build-test-release.md).
- **classify (sim)**: A feature-provided closure on a sim op or sim write, evaluated at decision time, that returns a diagnosis (`stale`, `conflict`, `duplicate`, `expected`) from content bookkeeping; a returned label takes precedence in `diagnose`. Code: `sim/src/oracle/knowledge.ts` -> `SimOp`, `SimWrite`; `sim/src/oracle/diagnose.ts` -> `diagnose`. Doc: [sim](sim.md).
- **clear (devtools)**: Overlay-only removal of cards and rows; runtime buffers are untouched and a remount backfills them again. Doc: [devtools](runtime/devtools.md).
- **Clock**: The injected time interface `{ now(), setTimeout(fn, ms), clearTimeout(h), afterTask(fn) }` through which all runtime time and scheduling go. Runtime code never calls `Math.random`, `Date.now`, `performance.now` or the global `setTimeout`, which keeps the sim deterministic. Defaults to `browserClock`; tests use `FakeClock`, the sim its `VirtualLoop` clock. Code: `packages/runtime/src/types.ts` -> `Clock`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **coalesce (action)**: Guard-tier `request` action, fetch only: do not send; wait (≤ 8 s) for the buffered response of an identical request that is in flight or settled ≤ 2 s ago, and answer a copy marked `x-genclass: coalesced`. Offered only when `ResponseCache.shareable` finds such a request. Code: `packages/runtime/src/observe/fetch.ts` -> `installFetch`; `packages/runtime/src/observe/cache.ts` -> `ResponseCache`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **COI (demos)**: Cross-origin isolation: the demos' Service Worker adds COOP `same-origin`, COEP `require-corp` and CORP `same-origin` headers so `crossOriginIsolated` is true and WASM threads are available to the model (`?coi=0` disables it). Doc: [demos](demos.md).
- **common random numbers (CRN)**: Pairing device that gives compared runs the same random draws. In the sim, counterfactual futures share one salt across all actions; in the demos, `World.rngFor(key)` gives the n-th occurrence of the same logical request or live event the same RNG in every mode, so Off/Guard/Heal comparisons measure GenClass rather than re-rolled network. Code: `sim/src/gen/trajectory.ts` -> `pointCosts`; `demos/src/server/core.ts` -> `World.rngFor`. Doc: [sim](sim.md), [demos](demos.md).
- **compact questions**: At a situation budget ≤ 1400 characters (`COMPACT_QUESTIONS_BUDGET`) every option description becomes `null` (bare labels), except vocabulary overrides of ≤ 24 characters; custom-action and plugin-label descriptions are dropped too. Instructions are unchanged. Code: `packages/runtime/src/situation/questions.ts` -> `buildQuestions`, `COMPACT_QUESTIONS_BUDGET`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md), [model-io-contract](model-io-contract.md).
- **COMPACT_BUDGET vs COMPACT_QUESTIONS_BUDGET**: Two distinct constants. `COMPACT_BUDGET` (1100, `serialize.ts`, exported from the root) is the budget at and below which section limits are smallest; `COMPACT_QUESTIONS_BUDGET` (1400, `questions.ts`, not exported from the root) is the threshold for compact questions. Code: `packages/runtime/src/situation/serialize.ts` -> `COMPACT_BUDGET`; `packages/runtime/src/situation/questions.ts` -> `COMPACT_QUESTIONS_BUDGET`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md), [model-io-contract](model-io-contract.md), [status-and-known-issues](status-and-known-issues.md).
- **consistency pair**: A `meta.pairs` entry (`neg`, `noul_choice`, `score_choice`) that the v2 training loss penalises to keep related answers coherent. Code: `jev_local/train/losses.py` -> `consistency_terms`. Doc: [genclass-model-lineage](genclass-model-lineage.md).
- **consistent snapshot**: A deep clone of all stores taken at a settled point where no violation newly broke (lingering ones allowed); `RuntimeImpl.snaps` keeps the last 8. Inconsistency `rollback` writes the last one back. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.settled`, `RuntimeImpl.rollback`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **consultable**: `RuntimeImpl.consultable()`: not paused, not destroyed, a decider exists and its `status.state` is `"ready"` or `"off"`. When false, every trigger runs its passive action without building a situation and no write is held; a default install today reaches this state because the unpublished model ends in status `error`. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.consultable`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md), [status-and-known-issues](status-and-known-issues.md).
- **consumed prefix (extension)**: Transcript words already acted on; later partials must still start with them (fillers and chain words ignored) or the stream freezes (`revised_after_act`), so an action never runs twice. Code: `extension/src/core/stream.js` -> `Stream`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md).
- **CONTRACT (legacy)**: `docs/CONTRACT.md` (the jev-local v0.1 build contract per workstream A–H, whose section D defines the CONTRACT-D row format), with `docs/CONTRACT-v2.md`, `docs/SPEC.md` and the other jev-local design docs. Legacy: runtime CONTRACT §1 says not to edit them. Doc: [genclass-model-lineage](genclass-model-lineage.md).
- **CONTRACT (runtime)**: `docs/runtime/CONTRACT.md`, the binding build contract owned by the lead: §0 ground rules (no hardcoded bug rules, one situation implementation shared with the sim, determinism through the injected `Clock`, sim and demos never read each other, no runtime dependency besides `onnxruntime-web`, builds on the VM), §0.5 product principles, §1 layout and owners, §2–§12 spec (§8 = the policy gate), §13 approved additions. Last edited in a53dd38, before batch 3, so it lags the code. Doc: [status-and-known-issues](status-and-known-issues.md).
- **CONTRACT-D row**: One JSONL training example `{id, split, family, state, questions, labels, meta}` (legacy CONTRACT section D, referenced by runtime CONTRACT §11), written by the sim and the curriculum and read by the trainer. Labels: choice `{label}` or `{dist}`, noul `{p}`, score `{level}` or `{dist}`; a qid without a label is packed but unsupervised. Code: `sim/src/types.ts` -> `Row`, `Label`; `jev_local/train/train.py` -> `parse_target`. Doc: [model-io-contract](model-io-contract.md), [sim](sim.md), [training](training.md).
- **Controller (extension)**: The extension's incremental voice decision loop (debounce, coalescing, stale rule, execute, consume, re-decide), a port of `jev_local/harness/controller.py`. See *harness (extension)*. Code: `extension/src/core/controller.js` -> `Controller`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md).
- **Controller (runtime)**: The seam between the decision flow and one trigger subject: `passive()` lets the subject proceed unchanged; `run(action)` performs a built-in action and returns `ActionEffect { changed, undo? }`, or throws/rejects, after which the passive action runs and the attempt is recorded `ok: false`. Held mutations also have `revertable()` / `revert()` for a late revert. Code: `packages/runtime/src/decide/exec.ts` -> `Controller`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **CORE (workstream)**: Owns `packages/runtime/**` except `packages/runtime/src/{model,devtools,adapters}/**`, including the situation wording and `packages/runtime/src/types.ts`; writes `packages/runtime/STATUS.md`. Doc: [status-and-known-issues](status-and-known-issues.md).
- **cost (sim)**: `runCost`, a run's cost relative to the ideal run: 1.0 × D(t) integrated over the 10 s after the decision + 4.0 × final client divergence + server damage (25 per extra/missing item, 6 per differing field or counter unit) + 0.8 × relation-violation seconds + 2.0 × relations still violated at the end + 1.5 × shown errors + 1.0 × uncaught errors + 0.08 × extra requests + 0.25 × pending seconds; "final" is decision + 15 s. Code: `sim/src/oracle/cost.ts` -> `runCost`, `W`. Doc: [sim](sim.md).
- **counterfactual run / counterfactual cost (sim)**: A sim re-run with a forced map (explored choices before decision `k`, action `a` at `k`, passive after), stopped at `t_k + 15 s` and required to reproduce the base run's fingerprints up to `k`; its `runCost` against the ideal run is the counterfactual cost of `a` at `k`. Code: `sim/src/run/runner.ts` -> `runScenario`; `sim/src/gen/trajectory.ts` -> `pointCosts`. Doc: [sim](sim.md), [model-io-contract](model-io-contract.md).
- **createRuntime**: The headless entry point (tests, sim, SSR): builds a `RuntimeImpl`, creating and owning a model host only when `decider` is `undefined` and `model` is an object. It can throw on malformed options and never sets `GenClass.runtime`. Code: `packages/runtime/src/index.ts` -> `createRuntime`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).

## D

- **D(t) (sim)**: Weighted client divergence of a run's stores from the ideal run's at the same time: each field contributes `w × d` with `d ∈ [0, 1]`, lists compared as multisets of item content. - **data-genclass-ignore**: Attribute that makes the DOM user observer skip events from inside the marked subtree, crossing shadow roots; the devtools host carries it. - **DeciderQueue**: The single-flight priority queue in front of the `DecisionProvider`: highest priority then oldest first; ≤ 32 queued (overflow drops the lowest-priority, oldest item); deadlines; a 10 s runtime-side timeout when there is no deadline; the answer cache; the last 20 provider latencies for the auto hold budget. Every fail-open path resolves `null`, never rejects. Code: `packages/runtime/src/decide/decider.ts` -> `DeciderQueue`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **Decision (extension)**: The extension controller's per-update result `{verdict, action, reason, seq, retryInMs, answers, latencyMs, risk}`. See *verdict (extension)*. Doc: [extension-and-benchmarks](extension-and-benchmarks.md).
- **Decision (runtime)**: The record `d<n>` made for every model answer to a trigger that reaches `onDecision` (never for `ask`/`decide`, while loading, for triage-skipped triggers or for failed queue items): diagnosis and its probabilities, `action` (the action that ran, else the model's top choice), `ran` (what actually executed, passive included), `executed`, `reason`, `candidate`, `mass`, facts (≤ 12), `answers`, `subjectRef`. `Detection` is a type alias. Code: `sim/src/run/runner.ts` -> `DecisionRec`. Doc: [sim](sim.md).
- **Decision Score (jevbench)**: `clip(1 − mean Brier / mean prior Brier, −1, 1)` per dataset. Code: `jev_local/bench/metrics.py` -> `decision_score`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md).

That package is not published at 654d822, so a default `GenClass.init()` ends with model status `error` and only observes. Code: `packages/runtime/src/model/host.ts` -> `DEFAULT_MODEL_BASE_URL`. - **defer (action)**: Guard-tier `mutation` action, offered while the write was deferred fewer than 2 times: wait for related in-flight ops (cap 10 s), then re-propose the write as a new trigger; after 2 defers it applies. Code: `packages/runtime/src/state/hub.ts` -> `StoreHub`. Doc: [state-and-adapters](runtime/state-and-adapters.md).

Also the action behind a late revert. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.gateMutation`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).

## E

- **Engine**: In the runtime, `Engine` (`engine.ts`) = `Packer` + an ORT session + calibration -> typed answers, building exactly the inputs `meta.json` declares. In `jev_local`, `Engine` is the Python engine protocol (`name`, `max_tokens`, `supports`, `count_tokens`, `evaluate` -> `EngineResult` of unrounded `RawDist`s) that `FastEngine` implements. Code: `packages/runtime/src/model/engine.ts` -> `Engine`; `jev_local/engine/base.py` -> `Engine`. Doc: [model-host](runtime/model-host.md), [genclass-model-lineage](genclass-model-lineage.md).
- **episode / muted**: The episode is the set of violation ids at the previous settled point; only violations not in it are fresh, so an inconsistency is raised once per episode. Muted ids are violations whose rollback was undone; they are not raised again until they hold once more. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.settled`. Doc: [state-and-adapters](runtime/state-and-adapters.md).
- **error (trigger)**: Raised by `rt.reportError` (also by the errors observer, and by app errors the hub catches while applying a held write); not held, priority 0; actions `ignore` (passive) and `rollback` (a chain revert, offered only when an ambient op existed). Fact E1 makes it always salient. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.reportError`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md), [decide-policy-actions](runtime/decide-policy-actions.md).
- **ettin**: The `jhu-clsp/ettin-encoder-*` family of ModernBERT-architecture encoders (MIT) behind every model here: 17m (d 256, 7 layers) for R17; 32m (d 384, 10 layers) for GenClass 0.1 and R32; 68m for the v2 benchmax models. Doc: [training](training.md), [genclass-model-lineage](genclass-model-lineage.md).
- **EventLog / RtEvent**: Ring buffer of `RtEvent { seq, t, kind, name, op?, cause?, data? }`, size `max(16, historySize ?? 500)`; kinds `user, op.start, op.end, state, error, nav, perf, storage, custom, decision, action`. `rt.history(n)` reads it and situation timelines are rendered from it; `touch()` re-notifies after a typing burst updates an event in place. - **events (runtime)**: `rt.on(type, fn)` types: `decide` (every runtime Decision), `detect` (detections), `act` (every non-passive action attempt), `event` (every RtEvent), `status` (model status changes and every `setMode` call), `report` (every report, even with `report: "silent"`). Listener exceptions are swallowed. Code: `packages/runtime/src/types.ts` -> `RuntimeEvents`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **evidence (devtools)**: The expandable block of a card, built from `runtime.explain(id)` with a fallback to the `Decision`: facts, model answers (top 6 bars per question), timeline, the exact situation text, metadata and a deny hint. Doc: [devtools](runtime/devtools.md).
- **expected**: The "nothing is wrong" diagnosis label; see *diagnosis*.
- **expired**: The hold-budget timer fired before the decision arrived, so the passive action already ran; a later gate-passing `discard` on a held write may still late-revert it. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.trigger`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **explain**: `rt.explain(id)` with a decision id `d<n>` or an action id `a<n>`: returns the message, decision, exact situation text, facts, timeline, answers and, if an action ran, the action and its `changed` sentence; `null` for unknown or evicted ids. Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.explain`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).

## F

- **F80**: The Azure VM size of the TRAIN nodes (`c01`, `c02`–`c11`), about $5.46/h per node (`training/LOG.md`); training runs use 8 ranks × 10 threads per node. Doc: [training](training.md).
- **facade**: `GenClass` (named and default export), the browser singleton around `createRuntime`. `GenClass.init(options)` never throws (it falls back to an inert runtime), is idempotent (a second call returns the first runtime and ignores its options), applies the kill switch and loads the local model by default; `GenClass.runtime` and `GenClass.destroy()` complete it. Code: `packages/runtime/src/index.ts` -> `GenClass`. Doc: [public-api-and-lifecycle](runtime/public-api-and-lifecycle.md).
- **fact**: `Fact { text, kind, neutral }`: a uniform English sentence computed per trigger by `computeFacts`; `neutral: false` makes the situation salient. Ordered non-neutral first, then by kind rank (invariant/transition/error 0, versions 1, repetition 2, inputs 3, outcome 4, baseline 5, concurrency 6, provenance 7, request 8, cache 9, delta 10, plugin 11), capped at 12 (`MAX_FACTS`). Plugin facts are always neutral. Code: `packages/runtime/src/situation/facts.ts` -> `computeFacts`, `orderFacts`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **fail open**: The universal fallback: no provider, provider not ready, any provider error, queue overflow, an expired deadline, hold-budget expiry or a throwing action all run the passive action, so a missing or slow model never blocks the app. Doc: [decide-policy-actions](runtime/decide-policy-actions.md), [model-host](runtime/model-host.md).
- **failure (baseline)**: A completion whose `EndOpts.failure` is set: network error, timeout, HTTP 5xx, 429 or 408 (a 404 is not a failure). Doc: [learn-situation-triage](runtime/learn-situation-triage.md).
- **failure (trigger)**: Raised when a request fails (see *failure (baseline)*) before the app sees the failure. Fetch failures go through the holdable failure gate (priority 2 when held), but are held only when a non-passive failure action is permitted: `retry` and `serve_cached` are heal tier, so in the default `guard` mode (and in `observe`) the failure is delivered at once and decided in the background (priority 1, 5 s deadline) unless a guard-tier custom action applies. XHR failures are never held (priority 1) and are detection-only. Actions `deliver` (passive), `retry`, `serve_cached`; fact F1 makes it always salient. Code: `packages/runtime/src/observe/fetch.ts` -> `installFetch`; `packages/runtime/src/observe/xhr.ts` -> `installXHR`. Doc: [learn-situation-triage](runtime/learn-situation-triage.md), [decide-policy-actions](runtime/decide-policy-actions.md).
- **fake runtime (sim)**: `createFakeRuntime`, a crude test double of the runtime used by default in the sim's vitest suites (`SIM_RUNTIME=real` switches to the real one). Its rows are marked `meta.runtime: "fake"`; `gen.js` uses it only with `--allow-fake`. Code: `sim/src/run/fake-runtime.ts` -> `createFakeRuntime`. Doc: [sim](sim.md).
- **FakeClock / FakeServer**: Runtime test kit: `FakeClock` is a virtual clock starting at `t = 1000` with `advance(ms)`, `flush()` and `runAll(maxMs = 120000)`; `FakeServer` is a virtual HTTP server exposed as `fetch` (routes keyed `METHOD pathname`, default latency 50 ms, unknown routes 404) that records hits. - **verdict (mutation)**: `Verdict = "apply" | "discard" | "defer"`, what a held mutation's promise resolves to. Code: `packages/runtime/src/state/hub.ts` -> `Verdict`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md), [state-and-adapters](runtime/state-and-adapters.md).
- **virtual utterance**: See *Tail / vid (extension)*.
- **VirtualLoop (sim)**: The sim's deterministic virtual event loop and clock (`schedule`, `afterTask`, `clockFor`, `settle`, `runUntil`); with keyed RNG forks it makes every seed reproducible. Code: `sim/src/loop.ts` -> `VirtualLoop`. Doc: [sim](sim.md).
- **vm.sh**: `scripts/vm.sh sync|run|exec|get <SLOT> ...`: rsync this repo to `~/gcl/<SLOT>` on the `train` VM and run commands there (default timeout 1800 s); it needs `~/.jev-local/azure_hosts` and `~/.ssh/jev_azure`, which are not in the repo. The original team ran every build and test this way because the author's Mac has 8 GB RAM (CONTRACT §0 rule 5). Current agent policy: install, typecheck, build and unit tests run locally; ask the user before running the sim, training, Playwright, model downloads, the demos' eval or any script that touches Azure. Code: `packages/runtime/src/types.ts` -> `Vocabulary`; `packages/runtime/src/situation/questions.ts` -> `diagnosisVocabulary`, `actionDescription`. ## W

- **W1–W11**: Engine and wire requirements for benchmax runs from `docs/benchmax-research/suite-reproduction-specs.md` §1.2 (e.g. W1 choice = argmax of unrounded probabilities with ties to the first key, W2 score fields, W3 precision, W4 refusal bodies, W5 overflow refuse/truncate, W9 one global calibration file, W10 model id never `jev-*`, W11 determinism). Code: `jev_local/bench/benchmax/runner.py` -> `check_model_id`; `jev_local/api.py` -> `ServeConfig`. Doc: [extension-and-benchmarks](extension-and-benchmarks.md), [genclass-model-lineage](genclass-model-lineage.md).
- **wait (action)**: Passive action of the `stall` trigger: keep waiting for the response. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **waits**: In `RuntimeImpl.trigger`, `opts.hold && permittedActions(policy, mode, actions).length > 0 && !paused`: whether the subject is actually held. A holdable trigger with nothing permitted runs its passive action at once and is decided in the background (detection only, 5 s deadline). Code: `packages/runtime/src/runtime.ts` -> `RuntimeImpl.trigger`. Doc: [decide-policy-actions](runtime/decide-policy-actions.md).
- **warm-up**: One forward pass (two on WebGPU) over `WARMUP_STATE` / `WARMUP_QUESTIONS` before a plan is accepted; it sets `status.warmupMs` (which seeds the auto hold budget) and seeds `status.latency`. Code: `packages/runtime/src/model/backend.ts` -> `ModelBackend`, `WARMUP_STATE`. Doc: [model-host](runtime/model-host.md).
- **wire request**: `{ state, questions }`, the only part of `EvaluateRequest` the model host uses; `trigger`, `subject`, `priority` and `timeoutMs` are scheduling and test metadata that never reach the packer. Code: `packages/runtime/src/model/protocol.ts` -> `ToWorker`. Doc: [model-io-contract](model-io-contract.md).
- **worker URL pattern**: The literal `new Worker(new URL("./worker.js", import.meta.url), { type: "module" })` in `defaultWorkerFactory` (and the literal `import("onnxruntime-web/webgpu" | "onnxruntime-web/wasm")` calls beside it) that app bundlers recognise; the browser-test build asserts they survive bundling. Code: `packages/runtime/src/model/host.ts` -> `defaultWorkerFactory`. Doc: [build-test-release](runtime/build-test-release.md).
- **workstream**: A team role that owns paths (runtime CONTRACT §1 and §13): lead, CORE, MODEL, UI, SIM, DEMOS, TRAIN, REVIEW. They communicate through `packages/runtime/STATUS.md` and per-requester NEEDS files; each has its own entry here. Doc: [status-and-known-issues](status-and-known-issues.md).
- **world (demos)**: One mock-server session in the demos' Service Worker, keyed by `live-<demo>-<rand>` or `trial-<demo>-<run>`; it owns state, chaos, request and event logs, SSE streams and timers. The page controls it only via `postMessage`, so GenClass never observes test traffic. Code: `demos/src/server/core.ts` -> `World`. Doc: [demos](demos.md).
