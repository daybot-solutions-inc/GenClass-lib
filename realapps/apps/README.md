# realapps app-authoring guide (for app-writing agents)

Project: /Users/meharkhanna/jev/GenClass-lib (branch `runtime`; never commit/push). Owner of realapps/: REAL.
You write small REAL web apps that run in headless Chromium with the real `@genclass/runtime`, driven by a
scripted user on virtual time against an in-page mock backend with chaos. Rows of training data are produced
from them. Diversity and realism are the point.

## App structure
`realapps/apps/<name>/manifest.ts` (default export AppManifest) + source files; entry = manifest.entry.
The page is `<div id="app"></div>` + bundle (ESM, production mode). Integration: `import { rt, flag } from
"../_shared/genclass"` (that module calls GenClass.init with harness options). Put app state in runtime stores
the way a developer would: `rt.atom(name, init)`, `useGenClassState` (React), `genclassEnhancer(rt,{name})`
(Redux / RTK `configureStore({ enhancers: (g) => g().concat(genclassEnhancer(rt, { name })) })`),
`genclass(rt, name)(creator)` (Zustand), `rt.guard(name, { get, set, subscribe })` for stores you own (Pinia, MobX):
writes made through the guarded atom go through GenClass's pipeline, writes made directly on the library store
are only traced. Some apps should be observe-only (`integration: "observe"`, no stores; e.g. jQuery DOM apps):
they still produce request/failure/stall/error rows and their divergence is measured on visible DOM text.
Feature flags: `flag("name", default)`; list options in `manifest.variants` with the FIRST option = the
default/correct/guarded behaviour (clean runs use the first option), later options = latent bugs or other guards.
Repeating an option weights it.

## Mock backend (ServerSpec, served in-page; see server.ts)
base "/api". Each collection `c` (path = c.path ?? c.name) gets:
GET /api/c (list; ?q= search fields, ?<filter>=, ?page=&limit= or ?offset=&limit=, ?sort=-field; envelope items|data|bare|results),
GET/PUT/PATCH/DELETE /api/c/:id, POST /api/c (create; Idempotency-Key header replays), POST /api/c/:id/<verb>
for `actions` ({inc, by} | {toggle} | {set}: relative, non-idempotent), POST /api/c/bulk {ids, op:"delete"|"patch", patch}
→ {results:[{id,ok,status}]} (some ids fail under chaos), `versioned: true` → PUT/PATCH need body.version or
If-Match = current version else 409 {error, current}. `live: true` → WebSocket topic c (connect to
`${location.origin.replace(/^http/,"ws")}/ws/<c>`): messages {type:"created"|"updated"|"deleted", collection, id, item, by?}.
docs: GET/PUT/PATCH /api/docs/<name> (versioned optional). counters: GET /api/counters/<n>, POST .../incr {by}, PUT {value}.
auth {ttlMs, rotate}: POST /api/auth/login {username,password} → {token, refreshToken, expiresIn}; POST /api/auth/refresh
{refreshToken} (rotate: an old refresh token → 401); `protected: true` collections need `Authorization: Bearer <token>`.
cart {collection}: writes to that collection answer with the FULL cart {items,count,total}; GET .../summary.
Item ids are content-derived; seed items may carry ids. Chaos (latency, spikes, outages 5xx/hang/neterr/empty,
rate limits 429, transient 5xx incl. after commit, replica lag, server bugs dropping fields, socket drops) is
generated by the harness; apps just see a flaky real-looking backend.

## The scripted user (manifest.affordances; see src/shared/manifest.ts)
Each affordance: id, kind (click|dblclick|type|clear|select|check|key|hover), CSS sel (">>>" pierces shadow
roots, for Lit), optional text filter list, nth (random match index < nth), values (type/select), weight,
mode (replace = newer intent on the same key supersedes; accumulate = each is a new intent), intent key option,
clear/enter for typing, dblclickP (accidental double click), impatientP (re-click while a request is in flight),
burst ([min,max] intentional repeats), after ([ids] usable only after one of them happened), then ([ids]
follow-ups, e.g. type then click Send), followOnly. Steps wait up to 2 s for their element to be visible (has
layout box) and are skipped otherwise. Events are dispatched like @testing-library/user-event (pointer/mouse/
focus, keydown/keypress/beforeinput/input/keyup with native value setters, select change, el.click() so
disabled buttons do nothing, Enter → form.requestSubmit()). Typing appends to the current value unless clear.

## Divergence/cost (what "correct" means)
Cost compares the app's registered stores AND the visible DOM text (innerText lines of domRoot, default body)
against an ideal run (zero latency, no failures, no accidental clicks). manifest.weights: per "store" or
"store.field" (error-message fields 0, loading/busy flags 0.1, inputs/drafts 0.3, versions 0). Show errors in
`[role=alert]` elements (counted as user-visible error episodes) — or set errorSelector. Declare relations for
derived values the app maintains (e.g. `{ name, fields: ["cart.total","cart.items"], check: s => !s.cart ||
s.cart.total === sum(...) }`, first field = the derived one): genuine broken relations are labelled
`inconsistent`. Keep displayed text deterministic (no real clocks; Date is virtual anyway).

Naming: the runtime redacts values whose field or store name is a secret word (password, token, secret, auth,
card number, cvv, ssn, ...), so do not call a store `auth` (use `session`). Affordance options added since the first
wave: `resets: [ids]` (e.g. sign-out makes `after: ["signIn"]` affordances unavailable again), `requires: "<css>"`
(a precondition checked when the step runs: skipped at once, without waiting, when no visible element matches; use it
for wizards and modal flows), and follow-ups (`then`) are skipped at once when their chain's first step was skipped.
`kind: "key"` affordances press the chosen `values` entry (e.g. ["ArrowDown", "Enter", "Escape"]). Collections can
declare `unique: [fields]` (409 on a clash) and `required: [fields]` (422 when missing).

Harness additions (wave 4 feedback):
- `after` is also enforced at run time: a step whose `after` affordances never actually ran is skipped ("after").
- `requires` is re-checked for 300 ms (virtual) before a step is skipped ("precondition"), so a few-ms difference in
  when a response lands cannot flip the session.
- List endpoints accept generic operators on any field: `f__in=a,b`, `f__gt|gte|lt|lte=v` (numbers or ISO strings),
  `f__ne=v`, `f__empty=true|false`; cursor pagination with `?cursor=<last id>` (or `?after=`), answered with
  `nextCursor` (or an `x-next-cursor` header for bare arrays).
- External events: `where` accepts `{ field: { $gt, $gte, $lt, $lte, $ne, $in } }`.
- `debug.js --traj --app a,b,c --seed 1-5` prints one line per (app, seed) and flags DEAD / NEARLY DEAD sessions
  (> 75% of base steps skipped while the ideal run is healthy).
- The page never scrolls (scroll events are real-time): apps must not load data on scroll.

## Determinism rules (the harness virtualises time and network; avoid what it cannot)
OK: setTimeout/setInterval/rAF/requestIdleCallback/MessageChannel/queueMicrotask, fetch, XMLHttpRequest (axios,
$.ajax, superagent), WebSocket, AbortController, AbortSignal.timeout, Date, Math.random, crypto.randomUUID.
AVOID: IntersectionObserver/ResizeObserver logic (they never fire), CSS transition/animation end events,
location.reload / full page navigation (SPA routing with history.pushState or hash is fine), IndexedDB,
FileReader, Workers, BroadcastChannel, EventSource, images/fonts gating logic, localStorage persistence across
runs (cleared each run). Do not code-split (single bundle).

## Test loop (your slot; first time: `cd realapps && npm install --no-audit --no-fund --ignore-scripts`)
  scripts/vm.sh run <slot> 'cd realapps && node build.mjs app1,app2 2>&1 | tail'
  scripts/vm.sh exec <slot> 'cd realapps && timeout 300 node dist/harness/debug.js --app app1 --seed 1 --show 1 --twice --steps'
    → ideal/base ok=true, steps mostly run (not skipped), net correlated N/N, triggers present, and
      "determinism: ... first diff -1" with equal snapshot/net/server hashes. Try seeds 1..6.
  scripts/vm.sh exec <slot> 'cd realapps && timeout 600 node dist/harness/debug.js --app app1 --seed 2 --traj --show 2'
    → rows produced, drops={} (no prefix-mismatch / cf-error). Inspect a few situations: they must make sense.
Each command is wrapped in a timeout; keep them short. The VM is shared and busy: run one test at a time.
Aim per app: 150–400 lines of real app code, several flags, 3–7 affordances, sessions that exercise the async
paths (loads, saves, polls, live updates), a manifest with weights/relations/external events where relevant.
