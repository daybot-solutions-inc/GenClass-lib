The problem

The worst bugs never throw an error.

A slow response lands after a fast one. A customer taps "Pay" twice. An endpoint starts failing at 2 a.m. and the app keeps hammering it. Error monitors see nothing, because nothing crashed. GenClass watches the timing and the data, not just the exceptions.

Stale responses

Search results for "pa" under a box that says "paris". GenClass sees the old response land over newer data and can drop its write.

Duplicate submits

A double-tap on a slow checkout. GenClass recognises the repeat and can merge it into the request already in flight.

Failure storms

An API that starts failing while the app keeps polling it. GenClass flags it with the failure streak and the baseline it broke.

Write races

A server echo overwriting what the user just typed. GenClass keeps the newer value.

Broken state

It learns rules your data keeps, like a cart total matching its lines, and reports the moment one breaks.

Slow and flaky calls

Latency far off the learned baseline, or a blip a careful idempotent retry would survive.

How it works

A model in the browser, deciding at the network boundary.

01

Observe

One line patches fetch, XHR, WebSocket and EventSource, and finds your React, Redux and Zustand state automatically.

02

Triage

Cheap facts are computed for everything. Only salient situations, like a response landing over newer data, reach the model.

03

Decide on-device

A 10 MB model in a Web Worker returns a calibrated diagnosis and action. No server, no API key.

04

Report or act

Observe reports in plain English. Guard can drop a stale write or merge a duplicate, with undo and an audit trail.

Install

One line, first in your app.

Observe mode is the default: it reports and changes nothing. Switch to guard when you trust what it sees.

// npm i @genclass/runtime, then first line of src/main.ts
import "@genclass/runtime/auto";          // observe
// import "@genclass/runtime/auto/guard";   // let it act
// instrumentation-client.ts (project root)
import "@genclass/runtime/auto";
<!-- first in <head>, no build step -->
<script src="https://cdn.jsdelivr.net/npm/@genclass/runtime@0.2.0"></script>
# detects your framework, shows the diff, asks, then writes
npx @genclass/runtime init
npx @genclass/runtime init --mode guard
npx @genclass/runtime remove   # undo exactly what init added

FAQ

Questions

Is GenClass free?

Yes. The runtime is open source under Apache-2.0 and free forever, including in commercial apps, with no usage limits. Cloud and Enterprise are optional paid products for dashboards, alerts, rollout controls, SSO and audit logs.

Does it need an account or an API key?

No. One script tag or import "@genclass/runtime/auto" is all it takes.

Is the demo above real?

Yes. This page loads @genclass/runtime@0.2.0 from npm and runs the model on your device. The demo calls a real API with real delays. Telemetry is off on this site.

Where does the AI model run?

In your users' browsers, inside a Web Worker on WebGPU or WASM. No server, no inference fees, and it keeps working offline.

Will it break my app?

The default mode only observes. Across 7 frameworks and 15 data layers it introduced no bugs in 3,510 runs. ?genclass=off turns it off instantly.

How often does it act today?

Rarely, by design. It is tuned to almost never be wrong when it acts, so at the default setting it acts on a minority of fixable cases. The benchmarks show the exact trade-off.
