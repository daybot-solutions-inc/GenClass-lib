Responses and push messages are judged before your app sees them. Cheap facts are computed for everything; only salient situations reach the model, so normal traffic costs nothing.

The pipeline

From fetch to fix in six steps.

01

Observe

Instruments fetch, XHR, WebSocket, EventSource, DOM events, errors, storage and timers, and links async work into causal chains.

02

Learn

Builds per-operation baselines for latency, failure and request rate, and relations that keep holding, like total == sum(price × qty).

03

Triage

Computes facts for every write and request. Only a response over newer data, a repeat, a failure streak or a broken relation goes to the model.

04

Decide

An 8.8M-parameter model (8.1M encoder, 0.7M heads) in a Web Worker reads the situation and returns a calibrated diagnosis and action.

05

Act

Only when acting beats doing nothing by the margin of the setting you chose: cautious, balanced or eager.

06

Explain

Every call is logged in plain English. rt.explain(id) returns the exact text the model read, and reversible actions can be undone.

Training

Trained in a simulated world, checked in real browsers.

Nobody has a dataset of what should have happened during a production race, so we built a world that generates one. Random apps run on the real runtime inside a deterministic simulator. For every decision, each candidate action is replayed and its cost measured, and the label is whatever turned out best. CPU nodes only, no GPUs.

About 17.6 million labeled rows (simulated gold, on-policy rounds, curriculum and real-browser gold) are what the shipped model trained on. The 51.8 million unlabeled rows were generated for a teacher-labelling step that was skipped because the 150M teacher did not beat the student; they are not used for training yet. The eval set is never trained on.

How a label is made

One decision, every possible future. The label is the cheapest outcome given only what the runtime could have known at that moment.
